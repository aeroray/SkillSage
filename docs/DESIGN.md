# Design System: SkillSage · 技匠

## Overview

**Creative North Star: 「安静的技匠工作台」(The Quiet Workshop)**

SkillSage 管理的是用户机器上一个**真实存在、所有 AI 工具都会读取**的共享目录。这个事实决定了整套界面的性格：这里的每一次点击都可能让某个技能在所有工具里消失。所以界面不追求吸引注意力，而是追求**让后果在动作发生之前就被看清**。

视觉上它是一件称手的工具，不是一个仪表盘。密度偏高但不拥挤：信息按「一屏能扫完」来组织，而不是按「一屏能塞下」来组织。颜色极度克制——整页通常只有一个青色出现，用于当前选中项或唯一的主操作；其余全部交给中性灰阶和留白。这里没有渐变、没有玻璃拟态、没有装饰性阴影；层次由**边框和表面色差**承担，阴影只用于真正浮起的层（弹窗、下拉、Toast）。

深浅两套主题不是同一套配色的反相，而是两个使用场景：浅色是白天办公室里的安静工具，深色是 OLED 屏上的工作台。两者共用同一套语义 token，因此组件代码从不感知主题。

**Key Characteristics:**
- 后果优先：破坏性操作必须显示**具体影响范围**（哪些技能、多少个），而不是抽象警告。
- 一个页面一个青色：主色只标记「当前」和「唯一主操作」，其余用中性色。
- 边框分层而非阴影分层：静态表面用 `1px` 边框 + 表面色差，阴影只给浮层。
- 状态必须真实：说不清楚的结论用专门的「无更新源」，绝不谎报「已是最新」。
- 全部文本 ≥ 4.5:1，含浅色模式的次要文字。

## Colors

整块调色板只有**一个色相家族**（青）+ 一套蓝灰中性色；状态色仅在表达状态时出现。

### Primary
- **深青 (Deep Teal)** (`#0d9488`): 主色填充。用于主按钮背景、选中复选框、焦点环、导航激活态的浅色底。是页面上唯一的高饱和色块。
- **深青·文字 (Deep Teal Text)** (`#0a7d70`): 主色的**文字**版本。凡是把青色当文字用（激活的导航项、Badge 文字、链接），都用它而不是 `#0d9488`——后者在浅色底上只有 3.40:1。
- **明亮青 (Bright Teal)** (`#75e6d7`): 深色模式下的主色。深色底上它有 8.35:1，因此文字与填充共用同一个值。

### Neutral
- **墨 (Ink)** (`#17202a`): 浅色模式正文与标题。对 `#f5f6f8` 达 15.21:1。
- **纸 (Paper)** (`#f5f6f8`): 浅色模式页面底色。刻意不是纯白，让卡片能靠色差浮起。
- **卡面 (Card)** (`#ffffff`): 浅色卡片、输入框、弹窗表面。
- **石板蓝灰 (Slate Blue Gray)** (`#5f6c7e`): 次要文字、占位符、图标。**不是** `#718096`：那个值在浅色三个表面上只有 3.54–4.02:1，不达标。当前值实测 4.71 / 4.94 / 5.34。
- **OLED 黑 (OLED Black)** (`#0b0d11`): 深色模式页面底色。
- **深色卡面 (Card Dark)** (`#11161d`): 深色卡片与弹窗，靠 6 级亮度差而非阴影浮起。

### Status
- **成功 (Success)** (`#0f9f94` 填充 / `#0b7a6f` 文字): 已分发、已保存、操作成功。
- **警告 (Warning)** (`#b7791f` 填充 / `#8f5d11` 文字): 需要用户整理或注意（如技能名不一致）。
- **危险 (Destructive)** (`#c2413d` 填充 / `#b23b37` 文字): 卸载、删除等不可逆动作。

### Named Rules
**「一个青色」规则。** 任意一屏内，主色只出现在「当前选中项」和「唯一主操作」上，不超过 10% 的面积。它的稀有就是它的意义——当青色出现时，用户不需要思考该看哪里。

**「文字色分离」规则。** 状态色有填充值和文字值两个 token。凡是渲染为文字（含 Badge、Toast、错误提示），一律用 `-text` 后缀的 token；`--color-success` 这类填充值在浅色模式下当文字只有 2.95:1。图标可以继续用填充值，因为图标是非文本内容，适用 3:1 门槛。

## Typography

**Display Font:** 系统无衬线栈（`-apple-system` → `Segoe UI` → `PingFang SC` → `Microsoft YaHei`）
**Body Font:** 同上
**Label/Mono Font:** 系统等宽栈，仅用于**代码、路径、版本号、提交哈希**等需要逐字符辨认的内容

**Character:** 完全依赖系统字体，没有自托管字体。这是刻意的：一个本地桌面工具应该看起来像系统的一部分，而不是一个网站。中英文混排由 `PingFang SC` / `Microsoft YaHei` 兜底，因此中文不会掉进衬线回退。字重只用到 400 / 500 / 600 三档，靠**字号和颜色**而不是字重来建立层级。

### Hierarchy
**四个字号，没有第五个。** 每一步都有一个明确职责，新增界面时从这四步里选，不要引入新值（`0.8rem` 这种介于两步之间的值曾经出现过，让筛选 chip 比紧挨着它的标签还大，正是「不协调」的来源）。

- **Dialog Title** (600, `1.125rem`/18px): 弹窗标题。全站唯一的第四步，也是唯一比 Title 大的一档——弹窗是聚焦表面，标题需要压过正文。每屏最多一个。
- **Title** (500, `1rem`/16px): 卡片标题、分区标题、详情里的关键数值。
- **Body** (400, `0.875rem`/14px): 正文、描述、按钮文字、导航项、技能名。桌面端基础字号。
- **Label** (400, `0.75rem`/12px): 元信息、时间戳、计数、徽章、筛选 chip、辅助说明。

字号只在必要时才升档：**能靠颜色和字重区分的，不要靠字号**。列表里大量出现的元素（技能名、路径、计数）一律停在 Body 或 Label，这也是密集列表能保持安静的原因。

### Named Rules
**「四步字号」规则。** 只用 `text-xs` / `text-sm` / `text-base` / `text-lg` 四档，且每档含义固定。不要写任意字号（`text-[0.8rem]`、`text-[13px]`）——它会绕开这套阶梯，并因为 `cn` 的 tailwind-merge 把基类的字号整个替换掉，产生设计者没预期的大小。

**「等宽即数据」规则。** 等宽字体只用于需要逐字符辨认的值（路径、哈希、版本）。不用它来营造技术气质。

**「字重不超三档」规则。** 只使用 400 / 500 / 600。层级由字号与颜色建立；再加字重会让密集列表变吵。

## Layout

固定桌面布局，最小窗口 `1200×800`，无移动端适配。窗口**没有原生标题栏**（`decorations: false`），顶部是应用自绘的 `36px` 标题栏；其下左侧 `228px` 固定导航栏，右侧内容区居中，最大宽度 `1600px`，内边距 `24px`（`lg` 断点升至 `28px`）。

**标题栏承担页头职责，页面不再画页头。** 标题栏分三段：品牌（宽度与导航栏一致，含 Logo 与中英文名）│ 当前页面名 + 该页操作（右对齐）│ 窗口控制（Windows/Linux）。页面名由路由决定，操作通过 `PageActions` portal 注入——操作留在页面自己的渲染树里，闭包始终读到最新状态，也不需要因为 props 变化而重新注册。

这样每个页面省掉约 `120px` 的纵向空间（标题、描述、外边距），首屏能多显示一整行内容。页面描述文字被移除：用户已经知道自己在哪个页面，重复一遍只占空间。

**页面本身永不滚动。** 外壳占满视口（`h-screen overflow-hidden`），每个页面是一个填满剩余高度的 flex 列：工具条固定在顶部，**只有列表区域滚动**。这样无论技能有多少，搜索框、筛选器和操作栏都始终可达，也不会出现第二条滚动条。需要滚动的内容一律使用共享的 `ScrollArea`。

**工作区卡片是页面的统一骨架。** 除了「设置」（内容型，整块滚动），其余页面都是同一个形状：一张占满剩余高度的 `Card`，其顶部是 `bg-muted/20` 的工具条（搜索、筛选、批量操作），下方一条 `Separator`，再下方是唯一滚动的列表区。新增页面沿用这个骨架，不要另起一套。

**栅格用容器查询，不用视口断点。** 内容区比视口窄 `228px`（导航栏）加两侧内边距，所以 `xl:`（视口 1280px）在最小窗口下永远不会触发，导致商店在 1200px 宽时只排两列。凡是「按可用宽度决定列数」的栅格，都挂在 `@container` 上并用 `@lg:` / `@4xl:` / `@6xl:` 变体。

**侧栏只做导航，不承载状态。** 侧栏是「去哪」，不是「有什么」。曾经在导航下方放了一张「共享技能目录」卡片（路径 + 计数），但它让侧栏变成第二个信息面板：每个页面都要看它一眼，而它承载的路径和计数在技能页里本来就是主要内容。侧栏现在只有导航项、更新提示和设置入口，用 `mt-auto` 把后两者压到底部。

间距严格使用 4px 的倍数，实际只用到 6 档：`4 / 8 / 12 / 16 / 20 / 24`。节奏是「组内紧凑、组间宽松」——同一张卡片内元素相距 8–12px，卡片之间相距 16–24px。标题上方的空间永远大于下方。

列表采用**作者分组的手风琴**，而不是平铺表格：技能天然按来源仓库聚集，分组后同一仓库的多个技能只需读一次作者名。列表行使用 `grid`，在 `lg` 以上展开为 `复选框 / 主信息 / 来源 / 分发状态 / 操作` 五列。

### Named Rules
**「4 的倍数」规则。** 所有间距必须是 4px 的倍数。出现 6px、10px、14px 这类值说明间距是随手写的，不是决定的。

**「标题上方更宽」规则。** 任何标题与其上方元素的距离，必须大于它与下方内容正文的距离。

**「页面不滚动」规则。** 滚动永远发生在列表区域，不发生在页面上。页头、搜索、筛选和操作栏必须始终可见。新增页面时，把滚动放在内容列表上，而不是包一层整页滚动容器。

**「按容器排栅格」规则。** 列数由容器实际宽度决定（`@container`），不由视口宽度决定。任何 `md:` / `xl:` 栅格断点都是错的——它不知道导航栏和内边距占掉了多少。

**「留白要有内容」规则。** 侧栏和页面的空白区域必须由真实状态填充（路径、计数、统计），不用装饰性图形或占位文案填。填不出内容说明布局该收缩，而不是该装饰。

**「侧栏只做导航」规则。** 侧栏是「去哪」，不是「有什么」。曾经在导航下方放了一张「共享技能目录」卡片（路径 + 计数），但它让侧栏变成第二个信息面板：每个页面都要看它一眼，而它承载的内容在技能页里本来就是主要内容。状态信息放在它所属的页面里。
**「页头即标题栏」规则。** 页面不画自己的页头。页面名在标题栏，页面操作 portal 到标题栏右侧，页面描述不写。省下的纵向空间留给内容——用户知道自己在哪个页面，重复一遍只占地方。
**「拖拽区用 deep」规则。** 标题栏的 `data-tauri-drag-region` 必须写成 `"deep"`。裸属性只在**直接点中该元素本身**时才能拖动（Tauri 用 `el === composedPath[0]` 判定），标题文字、Logo 这类子元素会变成拖不动的死区。`"deep"` 让整条都能拖，而按钮等可点击元素仍然照常拦截。窗口控制那一小段用 `"false"` 明确阻断拖拽。

**「双击归系统」规则。** 不要在标题栏上自己写 `onDoubleClick` 去最大化。Tauri 注入的拖拽脚本已经处理了双击（Windows 走 `internal_toggle_maximize`，macOS 在 `mouseup` 上判定以便取消），再写一遍会导致最大化后立刻还原。

**「控件小于容器」规则。** 按钮尺寸按所在容器选：标题栏和 chip 行用 `xs`（`28px`），卡片与工具条用 `sm`（`32px`），页面主操作用 `default`（`36px`）。控件撑满容器就失去了层次，chrome 里的控件必须明显小于内容区的控件。

**「不留空占位」规则。** 不要为了对齐而预留空白块。要等高，就让所有项的结构一致（字段数、行数相同），而不是给缺内容的项塞一个等高的空块——那正是要消除的东西。列表项不参与等高时，网格用 `items-start` 让各自贴合内容。

**「行高不由内容决定」规则。** 同一排里的对齐元素必须显式固定行高，不能让它随自身内容变化。商店卡片底部那行曾经是 `flex items-center`，于是带「同仓库还有 N 个」按钮（32px）的卡片把那行撑到 32px，没有按钮的卡片只有 16px——两行的「次安装」文字相差 9px。加 `min-h-8` 后两种情况都落在同一基线。**判断方法：把可选元素删掉再量一次，位置不应改变。**

**「图标按视觉重量配平」规则。** Lucide 的图形在 `24×24` viewBox 里留白不同，所以**相同的盒子尺寸并不等于相同的视觉大小**：`Square` 占 18 单位，`X` 只占 12 单位——同为 `14px` 时前者画出 `10.5px` 的墨迹，后者只有 `7px`。同一排图标要按墨迹配平，而不是按盒子：`X` 用 `size-5`、`Square` 用默认、`Minus` 用 `size-4`（横线只有高度没有宽度，同样需要放大）。

**「配置列全集，执行列相关项」规则。** 设置页列出完整清单（约 27 个工具），技能页只列出本机已检测到的工具。配置需要全集才能改到任何一项；执行只需要相关项，把 19 个用不上的工具铺进每一行会淹没真正要操作的两三个。判断标准是「这一屏是配置还是执行」，不是「哪个列表更全」。

**「不把猜测当事实」规则。** 数据来源的可靠程度必须在界面上可见。工具注册表里每条记录都带 `source` 文档地址和 `verified` 标记；来自第三方清单而非官方文档的路径必须显示「路径未核实」，而不是和已确认的条目长得一样。宁可让用户知道某条信息可能不对，也不要让不确定看起来确定。

**「让系统做系统的事」规则。** 选择文件或目录时调用原生选择器（`@tauri-apps/plugin-dialog` 的 `open`/`save`），不要让用户凭记忆敲绝对路径。手动输入保留为次选，用于选择器到不了的位置。

**「一种外观，多种语义」规则。** 组件可以因为**行为**不同而分开（Dialog 与 AlertDialog 的焦点管理、外部点击行为确实不同），但外观必须来自同一处定义。`dialog-shell.ts` 是浮层外观的唯一来源，`Dialog` 和 `ConfirmDialog` 都组合它。如果两个组件看起来像两个产品，那不是"语义不同"，是外观没有统一。

**「分区导航优于瀑布流」规则。** 设置类页面用「左侧分区导航 + 右侧单一分区内容」，不要用多列卡片瀑布。瀑布流没有阅读顺序——某一项落在哪一列只取决于上一列排满了没有——所以每次找设置都要两列都扫一遍。分区导航让"东西在哪"这个问题由导航本身回答。判断标准：这一页的内容之间是否**互相独立**；独立就该分区，有先后关系才该顺序排列。

**「列表行高不随数据增长」规则。** 列表里表示「多个同类状态」时，用**固定尺寸的符号 + 计数**，不要每个状态占一行。技能行的分发状态曾经是每个工具一行，装了八个工具就是八行；改成圆点 + `1/3` 后行高恒定 72px，信息量不变。判断方法：把这个字段的取值数量从 1 增加到 10，行高是否变化。

**「改主题色要换掉整套 primary」规则。** 主题色不能只覆盖填充色。`--app-color-primary`（填充）、`-foreground`（填充上的文字）、`-soft`（浅底）、`-border`、`-ring`、`-text`（作为文字时）是一个整体，任何一个漏掉都会让主题看起来「只换了一半」。曾经三个非默认主题都漏了 `-text`，于是蓝色按钮上的文字仍是青色——这正是「按钮背景是主题色但字还是绿的」的原因。新增主题时逐个核对这六个 token，并用对比度检查（≥ 4.5:1，含各自的 10% 浅底）。

## Elevation & Depth

以**边框分层**为主、阴影为辅。静态表面（卡片、列表行、分组）一律使用 `1px` 边框加表面色差来建立层次，不使用阴影——因为一屏可能有十几个卡片，每个都带阴影会让界面立刻变脏。

阴影只用于**真正浮起、可以关闭的层**：弹窗、下拉菜单、Toast、Tooltip。这套区分是硬性的。

### Shadow Vocabulary
- **`shadow-sm`** (`0 1px 2px rgba(23,32,42,0.045)`): 卡片贴地的极轻投影。深色模式为 `rgba(0,0,0,0.24)`。仅用于 `Card`。
- **`shadow-lg`** (`0 18px 50px rgba(23,32,42,0.14)`): 浮层。大偏移 + 大模糊，表达「这个层离开了页面平面」。深色模式为 `rgba(0,0,0,0.42)`。

### Named Rules
**「浮层才投影」规则。** 阴影是「这一层可以关闭、且盖住了下方内容」的信号。静态内容用边框，不用阴影。零偏移的彩色光晕属于装饰，不在这套系统里。

**「深浅不是反相」规则。** 深色模式不是浅色模式取反：它降低表面亮度差（`#0b0d11` → `#11161d` → `#171d25`），同时提高文字对比度（正文 17.72:1）。深色下的主色换成明亮青，因为深青在 OLED 黑上不够亮。

**「根节点也要上色」规则。** 主题背景必须同时画在 `html` 上，不能只画在 `body` 上。只画 `body` 时 `html` 与 `#root` 都是透明的（实测 `rgba(0,0,0,0)`），根画布保留 UA 默认的白色；合成器任何一次从根画布重建的画面——例如一个提升为合成层的浮层被移除时——都会在深色应用里闪出一帧白色。把背景画到 `html` 上，这种帧露出的就是应用背景。

**「浮层不用 backdrop-filter」规则。** 遮罩只用 `bg-black/45`（深色 `bg-black/70`），不加 `backdrop-blur`。整屏的 `backdrop-filter` 会把遮罩提升为合成层，而拆除一个合成层正是 Chromium/WebView2 上一帧闪烁的已知来源——弹窗关闭（例如商店的详情弹窗在安装完成瞬间关闭）正好触发这条路径。何况模糊在这里是装饰而非特定效果：这套系统用边框和 `shadow-lg` 建立浮层，纯遮罩已经足够把弹窗与页面分开。

## Shapes

圆角是**克制且成体系**的：`sm 8px` / `md 10px` / `lg 14px`，由 `--radius` 与 `--radius-lg` 两个 CSS 变量派生（`--radius-sm = radius - 2px`）。层级越高、面积越大，圆角越大：按钮和输入框用 `md`，卡片和弹窗用 `lg`，复选框用 `4px`（接近方形，表明它是可勾选的小控件）。

`Badge` 是唯一的完全圆角（`9999px`）元素——胶囊形让它一眼区别于方形的按钮，避免在小尺寸下与按钮混淆。

边框统一 `1px`，颜色比背景深一到两级（浅色 `#e1e6eb`，深色 `#29313b`）。没有 `2px` 及以上的边框，没有左侧色条，没有装饰性描边。

## Components

### Buttons
- **Shape:** 中等圆角（`10px` / `rounded-md`），内边距 `16px`，图标与文字间距 `8px`。
- **尺寸阶梯（4 档，按所在容器选）:**
  | size | 高度 | 用途 |
  |---|---|---|
  | `default` | `36px` | 页面主操作、对话框底部 |
  | `sm` | `32px` | 卡片内操作、工具条 |
  | `xs` | `28px` | 标题栏、chip 行等 chrome |
  | `icon` / `icon-sm` / `icon-xs` | `36` / `32` / `28px` | 图标按钮，与上面对应 |
  规则：**控件永远小于它所在的容器**。`36px` 的按钮放进 `36px` 高的标题栏会把整条撑满，失去层次。
- **Primary:** 深青底 + 白字。深色模式下**反转为浅色底 + 深字**（`dark:bg-foreground dark:text-background`）——OLED 上一块高饱和青色太刺眼，反转后用中性高对比承担主操作。
- **Hover / Focus:** 背景透明度变化（`hover:bg-primary/85`），`transition-colors`。焦点为 `2px` 主色环 + `border-ring`。
- **Outline:** 卡片底 + 边框，用于次级操作。**Ghost:** 无底无框，用于工具栏和行内操作。**Secondary:** 中性底，用于并列的非主要动作。**Destructive:** 危险色 10% 底 + 危险色文字，而不是实心红——卸载是重要但不该被误触的动作，实心红会过度吸引点击。

### Chips（筛选 ToggleGroup）
- **Style:** 未选中为透明底 + 常规文字；选中为 `bg-muted` + 前景色，圆角 `10px`，高 `28px`（`size="sm"`）。
- **State:** 单选。计数用**继承的前景色 + `opacity-80`** 渲染，而不是 `text-muted-foreground`——后者在 chip 底色上只有 3.54:1。计数为 0 的 chip 自动禁用。

### Cards / Containers
- **Corner Style:** `14px`（`rounded-lg`）。
- **Background:** 浅色 `#ffffff`，深色 `#11161d`。
- **Shadow Strategy:** 仅 `shadow-sm`，见 Elevation。
- **Border:** 恒有 `1px`。
- **Internal Padding:** `CardHeader` 为 `20px 16px`，`CardContent` 为 `0 20px`。

### Inputs / Fields
- **Style:** 透明底 + `1px` 边框，圆角 `10px`，高 `36px`。深色模式底色为 `input/30`。
- **Focus:** 边框转主色 + `2px` 主色环。
- **Disabled / Error:** 禁用降低不透明度；错误态边框转危险色并加危险色环。

### Navigation
- 左侧 `228px` 固定栏。项高 `40px`，圆角 `10px`，图标 16px + 文字。
- 默认态为蓝灰文字；hover 为中性底；**激活态为浅青底 + 深青文字**（深色下为深青底 + 明亮青文字）。这是「一个青色」规则最稳定的落点。
- 导航项下方不再有工作区卡片；底部是应用更新卡片与设置项，用 `mt-auto` 撑开，中间不留无意义的空洞。

### Title Bar（签名组件）
- 高 `44px`，`bg-sidebar` 底 + `1px` 下边框，与侧栏同色，视觉上连成一体。
- 三段：品牌（`228px`，与导航栏对齐，`1px` 右边框）│ 页面名 + 操作（右对齐）│ 窗口控制。
- **控件用最紧凑的一档**：标题栏里的按钮用 `size="xs"`（`28px` 高），窗口控制用 `icon-xs`（`28px` 见方）。默认的 `36px` 控件会把 `36px` 的标题栏撑满、失去呼吸感——chrome 里的控件要明显小于内容区控件。
- **Windows/Linux**：自绘最小化 / 最大化 / 关闭。关闭按钮 hover 用危险色 `15%` 底 + 危险色文字——与破坏性按钮同一套语言，不做实心红。最大化状态跟随窗口（监听 `onResized`），因为用户也可能双击标题栏或由系统最大化。
- **macOS**：保留原生红黄绿交通灯（`titleBarStyle: "Overlay"` + `trafficLightPosition: {x:16, y:22}` 对齐 `44px` 高度），品牌区让出 `76px` 左边距，不渲染自绘控制按钮。
- 窗口控制需要显式权限：`core:window:allow-start-dragging` / `allow-minimize` / `allow-toggle-maximize` / `allow-is-maximized` / `allow-close`。`core:window:default` 只给只读操作，不含这些。

### Store Card（签名组件）
- **等高**：卡片拉伸到行高（网格默认 `items-stretch` + 卡片 `h-full`，页脚用 `mt-auto` 压到底部）。
- **不显示描述**。描述长度不定，正是卡片高度参差的原因；它留在详情弹窗里，点一下就有一份完整说明。
- 去掉描述后每张卡片的结构完全相同（两行头部 + 一行页脚），所以等高不会产生任何空白。实测统一 `116px`。
- 卡片间距 `12px`（`gap-3`）。
- 关键点：**等高不是靠预留空白块实现的，而是靠让所有卡片结构一致**。之前用「固定两行描述占位」去凑等高，在已安装卡片上就渲染成一块 40px 的死白。

### Page Actions（签名组件）
页面通过 `PageActions` 把操作 portal 进标题栏，而不是渲染自己的页头。用 portal 而非回调注册表，是因为操作留在页面自己的渲染树里：闭包始终读到最新 state，也不需要因为 props 变化重新注册。

### Dialog / Modal（统一浮层）
- **一个外壳，两种语义。** 外观只定义一次（`components/ui/dialog-shell.ts`），由 `Dialog`（Radix Dialog，普通表单/详情）与 `ConfirmDialog`（Radix AlertDialog，必须作出决定的打断）共同组合。保留两套语义是因为行为确实不同：AlertDialog 把焦点放在最不具破坏性的动作上、点外部不关闭；但**外观必须一致**，否则同一个删除操作在两个页面看起来像两个产品。
- 结构固定为三段：**头部**（`px-5 py-4`，`pr-12` 给关闭按钮留位）│ **主体**（`px-5 py-4`，唯一滚动区）│ **页脚**（`border-t` + `px-5 py-4`，操作右对齐）。这三段用的是**应用自身的分带节奏**（工具条、卡片头、列表行同为 `20/16`），不是弹窗专属的一套间距。曾经用 `px-6 py-5` / `px-6 py-6`，于是弹窗成了全应用唯一自带间距刻度的表面，看起来比它背后的窗口更松——正是「不协调」的来源。头部到主体的间距因此是 `16 + 1 + 16 = 33px`，与主窗口的「工具条 → 分隔线 → 列表」完全一致。
- 关闭按钮 `absolute top-2.5 right-2.5`。它是 `32px`、标题是 `18px` 且 `leading-none`，在 `py-4` 下两者中心相差 `1px`；写 `top-3` 会低 `3px`。改头部内边距时同步改这里。
- 标题 `text-lg font-semibold`，**左对齐**。描述 `text-sm leading-6 text-muted-foreground`。
- 圆角 `rounded-lg`（14px），边框 `border-border`，阴影只用 `shadow-lg`（见「浮层才投影」）。
- 宽度三档：`sm`（确认类）/ `default`（表单、详情）/ `lg`。**不要临时写宽度**，按用途选档。
- 页脚是**组件的一部分**，不是各页面自己拼的按钮行。历史上每个对话框各写一个 `flex justify-end gap-2`，padding 各不相同，按钮位置随之漂移——这正是要消除的。
- 需要「左侧提示 + 右侧操作」时用 `DIALOG_FOOTER_NOTE`（`mr-auto`），而不是另起一个布局。

### Toast
- 顶部居中，宽 `420px`，`px-4 py-3`（16/12），`rounded-lg` + `shadow-lg`。与弹窗同为浮层，用同一个阴影 token。
- 卡片自身声明 `text-sm`，不靠继承：它挂在应用根节点（`16px` 正文）下，只声明 `text-sm` 的段落恰好正确，但任何后加的节点会继承 `16px`。**浮层容器必须声明自己实际渲染的字号**，这是全站统一的写法（`DIALOG_CONTENT`、`SelectContent`、`DropdownMenuContent` 同理）。
- 标题 `text-sm font-medium`，描述 `text-sm text-muted-foreground`，两者之间 `mt-0.5`。图标 `size-4`，与文字同轴。
- 空结果不得报成功：`variant` 决定图标与 `aria-live`，没有实际结论时用 `info` 而不是 `success`。

### Tooltip
- 反色表面（`bg-foreground` / `text-background`），`px-3 py-1.5`（12/6），`rounded-md`，`max-w-xs` + `leading-5` 以便放整句说明。
- 阴影用 `shadow-lg`，**不是 `shadow-md`**。主题只定义 `--shadow-sm`（卡片）与 `--shadow-lg`（浮层）两个 token；`shadow-md` 会落到 Tailwind 的内置默认值，那是一组硬编码的黑色，不随主题变化（浅色模式偏灰、深色模式不会加深），也不属于这套系统。DESIGN.md 的「浮层才投影」把 Tooltip 与弹窗、下拉、Toast 归为同一类，所以它们共用 `shadow-lg`。

### Settings（签名页面）
- **左侧 `176px` 分区导航 + 右侧单一分区内容。** 分区：外观 / 安全与连接 / AI 工具与分发 / 设备同步 / 关于与更新。
- 导航项复用主导航的样式语言：`36px` 高、`rounded-md`、激活态为浅青底 + 深青文字。同一套外观出现在两处导航，是刻意的——它们都是「选一个地方去」。
- **一次只渲染一个分区**，所以右侧不需要 `grid`，也不需要为了平衡两列高度而调整内容顺序。
- 只有右侧内容区滚动，导航固定。这样无论分区内容多长，导航都不会跟着跑。

### Tool Row（设置页的「AI 工具与分发」）
- **卡片是摘要，完整清单在模态框里。** 约 27 行内联会把整个设置页撑乱，而且这些是「配置一次」的内容，不是工作时会扫视的内容。卡片本身只显示两个数字（检测到的工具、需要分发）加工具 chip 和一个「管理工具与目录」按钮。
- **模态框只列已安装的工具**，其余收在「展开完整清单」后面。未安装的工具用户无法操作，平铺出来只会淹没真正相关的两三个。
- 每个工具一行：名称 + 「已安装」/「未检测到」徽章 + 已解析的技能目录（等宽字体，因为它是需要逐字符辨认的路径）。
- 未核实来源的工具额外显示「路径未核实」徽章，并用 tooltip 说明依据来自第三方清单。**不要把猜测当成事实展示**。
- **目录用系统选择器，不是让用户手打路径。** 主按钮打开原生目录选择框；手动输入保留为次按钮，用于选择器到不了的位置（网络共享、别的盘）。让用户凭记忆敲一个绝对路径是不合理的。
- 每行四个图标按钮，按「读→操作→改」排列：**复制路径**（复制后短暂变为对勾）、**打开目录**、**选择目录**、**手动输入路径**，最后是仅在已自定义时出现的**恢复默认**。都用 tooltip 说明，图标按钮不带可见文字。
- 唯一的设置是「读取公共技能目录」勾选框，下方一行说明当前后果（「技能已在该工具中可用，无需分发。」/「需要为每个技能单独建立链接。」）。用后果而不是机制来解释。
- 「恢复默认」只在已自定义时出现，避免出现一个点了没反应的按钮。
- 不显示「查看依据」链接：它服务于开发者核对注册表，不是用户在这个界面要做的事。依据 URL 仍保留在 `core/tools.rs` 里，需要时可在代码中查。
- **这一页列出完整清单，技能页只列出本机已检测到的工具。** 设置是「配置什么」，技能页是「现在做什么」——前者需要全集，后者只需要相关项。

### Distribution Status（技能行的分发列）
- **一行固定高度，不是每个工具一行。** 每个工具占一行会让行高随用户安装的工具数增长——装了八个工具就是八行。改为**圆点 + 计数**（`●○○ 1/3`）：已分发为实心主色圆点，未分发为空心点，悬停 tooltip 说明每个点对应哪个工具。
- 需要改动时去行菜单，不在列表里直接操作。列表是**读**，菜单是**写**。
- 没有需要分发的工具时显示「无需分发」，而不是留一个空列。
- 列宽固定，所以不同技能的行高一致；行高不随工具数变化。
- **只列出本机已检测到的工具**，加上已经持有链接的工具（这样卸载后的残留链接仍可移除）。

### Selection Action Bar（签名组件）
技能列表的工具栏在**有选中项时整体切换**为批量操作栏：`批量分发 · 检查更新(n) · 卸载(N)`，无选中时显示浏览态操作（`打开共享目录 · 更新全部 · 检查全部更新`）。

这是这套界面的核心交互决策：**选择本身没有意义，能对选择做什么才有意义**。因此每个动作按钮上的数字都是**该动作真正会作用的数量**，而不是选中总数——选中 4 个但只有 3 个有远端来源时，「检查更新」显示 3。用户不需要理解为什么数字对不上，因为界面上从未出现过一个会骗人的数字。

操作栏**不显示「已选 N 个」这类只读计数**，也**不提供「取消选择」**。每个按钮已经带着自己的数量，重复的计数只是噪音；而取消选择只要再点一次「全选」复选框即可，单独一个按钮是冗余。

### Distribution Filter（签名组件）
「分发」这一行把**已安装的工具直接做成徽章**，一行排列，点选即筛选。多选是**并集**——「看看我放进这些工具的技能」。

徽章用 `Badge` 的几何（`h-5`、`rounded-full`、`text-xs`）但实现为真正的 `<button>` + `aria-pressed`，因此会被读成「开关」而不是「标签」。

**反选是一个开关，不是第三个徽章**：它是整个选择的属性（「我没放进这些工具的」），而不是又一个可选的东西。只在有选中项时出现——反选空选择等于「不在零个工具里的技能」，也就是全部技能，等于没说。

工具多于一行宽度时**横向滚动且不显示滚动条**（`no-scrollbar` 工具类）：滚动条会与它旁边的徽章争夺注意力，而滚轮、触控板和键盘依然可达。

**这条规则是被三次迭代逼出来的**，值得记住为什么：
1. 下拉多选 + 四个结果 chip（任一 / 全部 / 均无 / 部分）——太多机器，用户得先给问题起个名字才能问它。
2. 两个互补 chip（已全部分发 / 有未分发）——选完工具就直接落进通常是空列表的那一个，空列表看起来像筛选坏了。
3. 现在：工具即控件，并集 + 一个反选开关。

### Workspace Card（签名组件）
除「设置」外，每个页面都是同一张占满剩余高度的卡片：顶部 `bg-muted/20` 工具条（搜索 / 筛选 / 批量操作），一条 `Separator`，下方是唯一滚动的列表区。它让四个页面的操作位置完全一致——搜索永远在左上、主操作永远在右上、列表永远在下方。工具栏高度固定，因此切换页面时它不会跳动。

### Segmented Range Control（签名组件）
技能商店的排行榜范围（热门 / 趋势 / 爆款）是**对同一个列表的单选过滤**，不是切换不同面板的标签页，因此用分段控件（`ToggleGroup`）而不是 `Tabs`。三个图标统一为中性色，只有激活段取强调色——三个不同颜色的图标会与内容争夺注意力，并破坏「一个青色」规则。

### Status Badge（签名组件）
技能的分发状态在**列表里**用圆点 + 计数表达（`●○○ 1/3`），在**详情里**用文字徽章（`Claude Code · 已分发`）。列表要能扫视，所以用符号；详情要能确认，所以用文字。两者都不是纯图标：纯图标没有可命名的 ARIA role，`aria-label` 会被丢弃，状态必须是真的文字才能被屏幕阅读器读到。

### Scan Summary（采纳技能页的工具条）
工具条**只有一行**，控件顺序与「我的技能」完全一致：左侧「全选 N 个」，右侧「打开共享目录」+ 主操作。两个列表页把同一个控件放在同一个位置，用户就不必在每页重新找它——这比让每页各自最优更重要。

目录**不是一个可点击的路径文本，而是一个按钮**（`打开共享目录`），与「我的技能」用同一个按钮做同一件事。路径仍然完整可读，收在按钮的 Tooltip 里，所以信息没有丢失；但按钮陈述的是**动作**，而路径只是事实。

这一栏曾经有三行——标题、摘要句、路径。摘要句（「1 个可直接采纳，1 个需先按 SKILL.md 整理名称」）试图解释数量差异，但它其实是**逐条说明的重复**：每一行已经带着自己的徽章与原因（`无法采纳` / `名称需整理` + 具体理由）。用一整页的篇幅复述每一行都说过的话，只在极少数「一个都采纳不了」的扫描里才值回票价，却要在每一次访问时都占三行。**当行内已经说明了原因，工具条就不要再总结一遍。**

### Update Panel（应用更新的签名模块）
状态行回答**从哪到哪**（`v1.0.2 → v1.0.3`，两端都用等宽字体），而不是只说「发现新版本 v1.0.3」——后者要用户自己回想当前版本才能判断这次升级有多大。

**发布说明必须显示。** 后端一直通过 `AppUpdateInfo.notes` 取回它，我们也按 `docs/releases/<tag>.md` 逐版本撰写它，但旧界面从未渲染，于是唯一能解释「为什么值得点立即安装」的信息恰好不在屏幕上。说明区高度受限（`max-h-56`）并自己滚动，这样一份长更新日志不会把操作按钮挤出视口。

**说明只作为文本渲染，永远不用 HTML。** minisign 签名保护的是*安装包*，不是清单；赢得竞速的镜像控制着这段文字。因此它经 `parseReleaseNotes` 解析成纯字符串再交给 React 转义，注入在结构上不可能发生。这条是安全约束，不是样式偏好——详见 `src/features/update/release-notes.ts`。

下载进度替换说明区，而不是插在它下方，因此面板在动作过程中不会长高。有 `Content-Length` 时用确定进度条；没有时用脉动的整条，而不是编造一个百分比——后者会宣称比我们知道的更多。

**侧栏的更新卡片只负责导航，不负责安装。** 卡片按钮是「查看更新内容」，点击后跳到 `/settings?section=about`，把用户带到说明所在的页面；安装按钮只存在于更新面板里，也就是说明已经在屏幕上的地方。此前卡片直接调用 `install()`，于是**唯一宣告更新的表面，恰好也是唯一跳过发布说明的表面**——用户可以在从未看过改动内容的情况下替换整个应用，而说明其实早就取回来了。这也违反上面的「发布说明必须显示」和「侧栏只做导航」：安装是一个需要先读再决定的动作，不属于每个页面都能看到的地方。卡片在下载中仍然可点（文案变为「查看更新进度」），这样它同时是回到进度条的入口。

**设置分区在 URL 里，不只在组件状态里。** `/settings?section=<id>` 是分区的唯一来源，侧栏卡片因此能直接指向「关于与更新」，而不是把用户丢在「外观」让他们自己找。缺省或无法识别的值回落到「外观」，所以手改 URL 不会渲染出空白面板。「外观」作为默认值不写进 URL。

## Do's and Don'ts

### Do:
- **Do** 让每个批量操作按钮显示它**真正会作用的数量**（`卸载（4）`、`检查更新（3）`），即使与选中数不一致。
- **Do** 破坏性操作展示具体影响范围：批量卸载对话框列出所有受影响的技能名。
- **Do** 把状态色当文字用时改用 `-text` token（`text-destructive-text`，而非 `text-destructive`）。
- **Do** 用 `1px` 边框 + 表面色差表达静态层次，用 `shadow-sm` / `shadow-lg` 只表达浮层。
- **Do** 用 `sr-only` 补充图标按钮的状态文本，而不是给无 role 的 `<span>` 加 `aria-label`。
- **Do** 在按钮禁用时用 `<span>` 包裹再挂 Tooltip，否则禁用按钮会吞掉指针事件，用户看不到原因。
- **Do** 让「打开目录」这类动作在目标不存在时降级到**最近的存在祖先**并说明打开了哪一个，而不是静默失败——一个看起来坏掉的按钮比一个打开上级目录的按钮更让人困惑。
- **Do** 让可筛选的实体本身成为控件（工具徽章），而不是把它藏进下拉再配一组「结果模式」chip：前者展示可筛选的范围，后者要求用户先给问题命名。
- **Do** 横向滚动的徽章行用 `no-scrollbar`：滚动条会与徽章争夺注意力，而滚轮与键盘仍然可达。
- **Do** 让工具条保持一行；当行内已经逐条说明了原因，工具条就不要再总结一遍——复述每一行都说过的话，只在极少数情况下值回票价。
- **Do** 让同一个控件在同类页面上出现在同一个位置（「全选」永远在工具条最左），即使用户不会同时看到两页。
- **Do** 让「打开目录」是一个按钮而不是可点击的路径文本：按钮陈述动作，路径只是事实；路径收进 Tooltip，信息不丢。
- **Do** 把网络取回的说明文字解析成纯字符串交给 React 渲染；清单不在安装包签名覆盖范围内，`dangerouslySetInnerHTML` 会让赢得竞速的镜像获得注入能力。
- **Do** 用 `scrollbar-subtle` 给非 Radix 的有界滚动区做主题化滚动条：平台默认滚动条不属于任何设计系统，是一个面板最容易被看出来的未完成角落。
- **Don't** 用「打开目录」顺手创建缺失的目录：`ToolResolver::detected` 把目录（或其父目录）存在当作「已安装」的信号，创建目录会让未安装的工具在所有技能行里都显示为已安装。
- **Do** 保持所有正文与占位符文字 ≥ 4.5:1，图标 ≥ 3:1。
- **Do** 让新页面沿用「工作区卡片」骨架：固定工具条 + 唯一滚动列表区。
- **Do** 用容器查询（`@container` + `@lg:`/`@4xl:`）决定栅格列数。
- **Do** 让侧栏只做导航；状态信息放在它所属的页面里。
- **Do** 让每个会关闭自身的破坏性或写入性操作在关闭前给出结果：商店的安装成功后弹窗立即关闭，因此成功提示必须在关闭前发出，否则一次成功的安装**没有任何可见反馈**。`useSkillInstall` 把 `InstallResult` 交给 `onCompleted`，正是为了让调用方能说出装的是哪个技能。
- **Do** 把页面操作 portal 到标题栏，页面自己不画页头。
- **Do** 给标题栏的拖拽区写 `data-tauri-drag-region="deep"`，否则子元素拖不动。
- **Do** 按容器选按钮尺寸：标题栏用 `xs`，卡片用 `sm`，页面主操作用 `default`。
- **Do** 让卡片和列表项只占自己内容的高度，网格用 `items-start`。
- **Do** 让配置界面列出全集，让执行界面只列出本机相关的项。
- **Do** 把数据来源的可靠程度显示出来（「路径未核实」+ 依据链接）。
- **Do** 给同排需要对齐的行加显式 `min-h-*`；判断方法是删掉可选元素后位置不变。
- **Do** 用原生文件/目录选择器代替让用户手打路径。
- **Do** 让所有浮层的外观来自 `dialog-shell.ts`，页脚是组件的一部分。
- **Do** 设置类页面用分区导航，一次只渲染一个分区。
- **Do** 让列表行高恒定：同类状态用符号 + 计数，不要每个占一行。
- **Do** 新增主题时补齐 primary 的六个 token（含 `-text` 与 `-foreground`）并做对比度检查。

### Don't:
- **Don't** 用 `text-muted-foreground` 渲染彩色底上的文字（chip、彩色 Badge）——实测只有 3.5:1 左右。
- **Don't** 给静态卡片加阴影；一屏多个阴影会让界面立刻变脏。
- **Don't** 用渐变文字、玻璃拟态、`2px+` 边框、或彩色左边条。
- **Don't** 用实心红表达破坏性操作；用危险色 10% 底 + 危险色文字。
- **Don't** 把等宽字体用于非数据内容当作「技术感」装饰。
- **Don't** 谎报状态：无法判断的用「无更新源」，不要归入「已是最新」。
- **Don't** 让同一个标签指向两个不同的东西（「打开技能目录」曾同时表示「打开此技能文件夹」和「打开共享根目录」）。
- **Don't** 引入移动端断点；这是最小 `1200×800` 的桌面应用。
- **Don't** 用视口断点（`md:` / `xl:`）排内容区栅格；它不知道导航栏占了多少宽度。
- **Don't** 用装饰性图形或占位文案填充空白区域。
- **Don't** 把状态信息塞进每个页面都看得见的侧栏；它属于具体页面。
- **Don't** 给页面画自己的页头（标题 + 描述）；标题栏已经有页面名。
- **Don't** 在标题栏上自己实现双击最大化；Tauri 的拖拽脚本已经做了。
- **Don't** 用裸 `data-tauri-drag-region`；子元素会变成拖不动的死区。
- **Don't** 为对齐预留空白块；内容少就让元素矮一点。
- **Don't** 把全部注册项铺进执行界面；用户只关心本机相关的那几项。
- **Don't** 让未核实的数据和已确认的数据长得一样。
- **Don't** 让同一排的对齐元素依赖内容高度；可选元素出现或消失都会错位。
- **Don't** 要求用户手动输入文件或目录路径作为唯一方式。
- **Don't** 让两个语义不同的浮层长成两个样子；外观必须来自同一处。
- **Don't** 在对话框里各写一套按钮行；用 `footer`。
- **Don't** 用多列卡片瀑布排设置项；那没有阅读顺序。
- **Don't** 让列表行高随取值数量增长。
- **Don't** 只覆盖主题的填充色而不覆盖它的文字色。
