## What's New · 本次更新

### 🧩 技能商店 · Skill Store

- 已安装的技能在商店卡片上直接显示「卸载」按钮，不再是一个禁用的「已安装」标签。此前它只是重复了卡片已经说明的状态，然后让用户自己去「我的技能」页面才能撤销；现在点击即可卸载，确认对话框与「我的技能」完全一致。
  Installed skills now show an 卸载 button on their store card instead of a disabled 已安装 label. The label only restated what the card already said and left the user to go to 我的技能 to undo it; the button uninstalls directly, with the same confirmation dialog as 我的技能.

- 技能详情页底部按钮会跟随安装状态：已安装显示「卸载」，未安装显示「开始安装」。此前对已安装的技能仍然显示「开始安装」——而这恰好是用户在这里唯一不能有效做的事。
  The detail footer now follows the skill's state: 卸载 when installed, 开始安装 when not. It previously said 开始安装 for an installed skill, which is the one thing the user cannot usefully do from there.

- 修复安装完成后没有任何成功提示的问题。弹窗在安装成功的瞬间关闭，而商店此前从未接入提示系统，因此一次成功的安装唯一的反馈只是卡片悄悄变成「已安装」。现在会提示「安装完成」并说明装的是哪个技能。
  Fixed a successful install producing no confirmation at all. The dialog closes the moment the install resolves and the store never used the notification system, so the only feedback was a card quietly switching to 已安装. It now reports 安装完成 and names the skill.

### 🔄 应用更新 · App Updates

- 侧栏的更新提示卡片改为先带用户查看更新内容，而不是直接安装。此前它的按钮是「立即安装」，于是唯一宣告更新的地方，恰好也是唯一跳过发布说明的地方——可以在从未看过改动内容的情况下替换整个应用。现在按钮是「查看更新内容」，点击后进入设置中的更新页面，在那里阅读说明后再决定安装。
  The sidebar's update card now takes you to the release notes instead of installing directly. Its button used to be 立即安装, which made the one surface that announces an update also the one that skipped the notes — you could replace the app without ever seeing what changed. It now reads 查看更新内容 and opens the update section in Settings, where you read the notes before deciding to install.

- 设置页面现在可以通过链接直接打开某个分区（例如更新页面），浏览器前进/后退也会正确切换分区。
  Settings sections are now addressable by link (for example the update page), and browser back/forward switch sections correctly.

### 🎨 界面修复 · Interface Fixes

- 修复关闭弹窗时可能出现的白屏闪烁。定位到两个成因并都已修复：主题背景此前只画在 `body` 上，根画布因此保留浏览器默认的白色；弹窗遮罩使用了整屏模糊，会把遮罩提升为独立合成层，而拆除该层正是这类闪烁的来源。现在背景同时画在根节点上，遮罩只保留纯色。如果你仍然看到闪烁，请反馈。
  Fixed a possible white flash when a dialog closes. Two causes were identified and both are fixed: the themed background was painted only on `body`, leaving the root canvas at the browser default white, and the dialog scrim used a full-screen blur, which promotes the scrim to its own compositor layer — tearing that layer down is a known source of this kind of flash. The background is now on the root as well and the scrim is a flat colour. If you still see it, please report it.
