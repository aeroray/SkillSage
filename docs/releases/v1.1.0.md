## What's New · 本次更新

### 🔗 外部链接 · External Links

- 商店详情里的「在 skills.sh 打开详情」、设置页的「GitHub 项目」和「产品主页」以前点击没有反应。这个应用没有注册新窗口处理器，也没有安装 opener 插件，所以 WebView 会直接拒绝 `target="_blank"` 导航——按钮看着能点，实际什么都不会发生。现在这些链接交给系统浏览器打开。
  The “在 skills.sh 打开详情” link in the store detail and both About links in Settings did nothing when clicked. The app registers no new-window handler and ships no opener plugin, so the WebView denies `target="_blank"` navigation — the controls looked clickable and were inert. They now hand the URL to the system browser.
  Only `https` URLs without embedded credentials are accepted, and the check happens in the backend, not just the renderer.

### 🛡️ 卸载与数据安全 · Uninstall and Data Safety

- **修复卸载失败时完全没有提示的问题。** 商店页的卸载失败后，确认框照常关闭，页面也不显示任何错误——权限不足或磁盘错误看起来和成功一样。现在失败原因会在弹窗关闭前提示，弹窗保持打开以便重试。
  **Fixed a failed uninstall producing no feedback at all.** On the store page the confirmation dialog closed as usual and the page rendered no error, so a permission or disk failure looked exactly like a success. The reason is now reported before the dialog closes, and the dialog stays open so the action can be retried.

- **修复「接管」会删除它承诺保留的目录。** 冲突对话框的按钮是「备份后继续」，说明写着「把现有内容改名保留」，但安装成功后会把这个备份目录递归删除——用户为了不丢内容才选择接管，结果得到的是不可恢复的删除。现在备份会被真正保留。
  **Fixed takeover deleting the directory it promised to keep.** The conflict dialog's button reads 备份后继续 and says the existing content will be kept under a renamed folder, but a successful install recursively deleted that backup — the one flow a user chooses *because* it preserves their folder destroyed it. The backup is now genuinely kept.

- **修复锁文件短暂「不存在」的窗口。** 替换锁文件时先把旧文件改名挪开、再挪入新文件，两步之间文件不存在；若此时崩溃，所有已安装技能都会变成未跟踪状态，并发读取也可能看到空列表。现在改为单次原子替换。
  **Fixed a window in which the lock file did not exist.** Replacing it renamed the old file aside and only then moved the new one in; between the two steps the file was absent, so a crash there untracked every installed skill and a concurrent read could see an empty library. It is now a single atomic replace.

### 🧭 状态与反馈 · Status and Feedback

- **「检查更新」不再把没检查的技能报成「均为最新」。** 后端会跳过单个技能的检查失败，只返回成功项，而界面此前按「请求的数量」报告结果——断网时会显示「已检查 3 个技能，均为最新」并配绿色对勾。现在空结果会说「未取得检查结果」，并说明有几个未能检查。
  **检查更新 no longer reports unchecked skills as 均为最新.** The backend skips individual check failures and returns only successes, while the UI counted the *requested* ids — so a broken network produced “已检查 3 个技能，均为最新” under a green check. An empty result now says 未取得检查结果 and reports how many could not be checked.

- **修复切换「读取共享技能目录」会清空该工具自定义目录的问题。** 这个开关只发送标记位，而保存时整条覆盖了工具配置，导致用户自定义的目录被删除。现在改为按字段更新。
  **Fixed toggling 读取共享技能目录 wiping that tool's customized directory.** The toggle sends only the flag, but saving replaced the whole override, deleting the user's custom path. Overrides are now patched field by field.

- **修复商店详情页会显示上一个技能的冲突检查错误。** 打开新技能时只清理了安装错误，没有清理冲突检查错误。
  **Fixed the store detail dialog carrying a stale conflict-check error from the previous skill.** Opening a new skill cleared the install error but not the conflict-check error.

- 同步导入的「全不选」不再被当成「全部导入」；批量卸载不再为每个技能各刷新一次；采纳技能时，仅大小写不同的目录名现在可以修复。
  An empty sync selection is no longer read as “import everything”; batch uninstall refreshes once instead of once per skill; and adopt can now repair a folder name that differs from `SKILL.md` only in case.

### 🔄 应用更新 · App Updates

- **镜像响应不再无上限缓冲。** 更新清单和发布元数据现在有大小上限，镜像无法用超大响应把内存吃满。
  **Mirror responses are now bounded.** Manifest and release-metadata bodies have a size cap, so a hostile or broken mirror cannot exhaust memory with an oversized response.

- **更新器不再可能永久卡住。** 之前对镜像的请求没有超时，某个节点完成握手后停止发送就会让检查或安装一直挂着，界面停在「检查中」。现在设置了连接与读取超时。
  **The updater can no longer hang forever.** Requests to mirrors had no timeout, so a node that completed the TLS handshake and then stalled left the check or install waiting indefinitely with the UI stuck on 检查中. Connect and read timeouts are now set.

- **安装包会与它声明的版本核对。** 签名只能证明「发布密钥签过这段字节」，不能证明它属于当前版本，因此镜像理论上可以用旧版的签名包冒充新版本，完成一次静默降级。现在下载后会用 GitHub 的发布元数据核对安装包大小，不一致即中止。签名校验在任何路径上都没有被绕过。
  **The installer is now checked against the version it claims to be.** A signature proves the release key signed *some* bytes, not that they belong to this release, so a mirror could in principle serve an older signed installer under a newer label — a silent downgrade. The downloaded package's size is now cross-checked against GitHub's release metadata and the install aborts on a mismatch. Signature verification is never bypassed.

- 列出一个 GitHub 仓库的技能时，不再把每个候选技能的全部文件都下载一遍；单个候选读取失败也不会再让整个列表失败。
  Listing a GitHub repository's skills no longer downloads every file of every candidate, and one unreadable candidate no longer fails the whole listing.

### 🧹 其他 · Other

- 移除了开发用的 Ainotation 注释插件及其依赖（连带 104 个传递包）。
  Removed the development-only Ainotation annotation plugin and its dependencies (104 packages in total).

- 工具目录路径包含 `%` 或 `"` 时不再尝试「转义」——cmd.exe 无法承载这两个字符，之前的转义会让链接建到与记录不同的路径上。现在直接拒绝并说明原因。
  Tool directory paths containing `%` or `"` are no longer “escaped” — cmd.exe cannot carry those characters, and the old escaping created a link at a different path than the one recorded. They are now rejected with an explanation.

- README 改为英文为默认版本，并新增简体中文版（`README.zh-CN.md`）。补充了缺失的 MIT LICENSE 文件。
  The README is now English by default, with a Simplified Chinese translation at `README.zh-CN.md`. The previously missing MIT LICENSE file was added.
