# Skillsage 需求文档（最终版）

## 1. 项目定位

**Skillsage** —— 面向 Windows 和 macOS 的 AI Agent 技能管理器。用户可以从 skills.sh 浏览/搜索技能、从 GitHub URL 直接安装、或从本地导入，安装到私有中央仓库，再按需通过链接分发到主流 AI 工具。支持版本管理、更新回退、跨设备同步、存量技能迁移。

## 2. 技术栈

| 层 | 技术 |
|----|------|
| 桌面框架 | Tauri 2 |
| 前端 | React + shadcn/ui + pnpm |
| 后端 | Rust（核心逻辑完全自研，不依赖 `npx skills`） |
| 后端关键依赖 | reqwest、tokio、serde、serde_yaml、scraper、keyring、blake3、thiserror、dirs、tracing |

## 3. 平台与分发策略

| 平台 | 分发方式 | 备注 |
|------|---------|------|
| macOS | 符号链接（symlink） | 零拷贝，即时同步 |
| Windows | 目录联接（junction） | 无需管理员权限，仅限同盘符 |

**不支持复制模式**，中央仓库是唯一数据源，所有工具目录中的链接指向它。

## 4. 首发支持工具

| 工具 | 开发方 | 全局路径 |
|------|--------|---------|
| Claude Code | Anthropic | `~/.claude/skills/` |
| Cursor | Cursor Inc. | `~/.cursor/skills/` |
| GitHub Copilot | Microsoft | `~/.github/skills/` |
| OpenAI Codex CLI | OpenAI | `~/.codex/skills/` |
| OpenCode | 开源社区 | `~/.config/opencode/skills/` |

**不支持的说明**：Amp 等使用通用共享目录（`.agents/skills/`）的工具，不符合最小权限原则，明确不支持。不提供用户自定义工具注册功能。

## 5. 私有中央仓库结构

```
~/.skillsage/
├── remote/              ← 从商店安装，按作者组织
│   ├── <作者名>/
│   │   ├── <技能名>/
│   │   │   ├── SKILL.md    ← 核心文件（必需）
│   │   │   ├── scripts/    ← 可选
│   │   │   ├── references/ ← 可选
│   │   │   └── assets/     ← 可选
│   │   └── ...
│   └── ...
├── local/               ← 本地导入，扁平结构，同名走覆盖/重命名
│   ├── <技能名>/
│   │   └── SKILL.md
│   └── ...
├── lock/
│   ├── skill-lock.json  ← 全局锁文件（来源、版本指针历史、hash、distributedTo、链接路径）
│   └── snapshots/       ← 更新时的旧版本快照（仅保留最近一次）
└── tmp/                 ← 临时目录（安装/更新时使用）
```

## 6. 产品功能清单

| 功能 | 说明 |
|------|------|
| 技能商店浏览 & 搜索 | 搜索走 `api/search` JSON 接口，排行榜走 `skills.sh` 页面 |
| 技能详情 | 抓取 `www.skills.sh/<作者>/<仓库>/<技能名>` HTML 页面提取字段 |
| 技能安装（从商店） | 自研下载器，从 GitHub 拉取技能内容到 remote 区 |
| 技能安装（GitHub URL） | 解析 URL 为 owner/repo/skillPath，复用商店下载逻辑 |
| 技能安装（本地导入） | 自动解析 SKILL.md frontmatter，校验失败则提示用户 |
| 技能分发 | 安装时勾选目标工具，通过 junction/symlink 分发到全局路径 |
| 调整分发 | 技能详情中调整工具勾选，增删对应链接，不改中央仓库内容 |
| 检查更新 | 用户手动触发，基于 lock 中的 source 去 GitHub 拉取最新版，对比 hash |
| 技能更新 | 备份当前版本（快照 + 版本指针 append）→ 原子替换 → 更新 lock |
| 版本回退 | 优先从 GitHub 拉取指定 commit 内容，不可得时走本地快照兜底，都失败则报错 |
| 技能卸载 | 删除中央仓库 + 删除所有关联链接，不做回滚，失败项可重试 |
| 本地导入 | 支持目录/单文件，自动解析 frontmatter，以 `name` 为权威标识 |
| 跨设备同步 | remote 导出 JSON 清单（不含内容），新设备按需重新拉取 |
| 存量技能迁移 | 扫描工具目录 + 公共目录，识别条目类型，接管实体后建链接 |
| 设置 | GitHub Token 配置（本地加密存储，不参与同步）、代理配置 |

## 7. 安装来源对比

| 来源 | 前置识别 | 下载逻辑 | lock 记录 | 更新/回退 |
|------|---------|---------|-----------|----------|
| 商店 | skills.sh 搜索/排行榜 | 同一下载器 | 支持 | 支持 |
| GitHub URL | 解析 owner/repo/skillPath | 同一下载器 | 支持 | 支持 |
| 本地导入 | 文件系统定位 SKILL.md | 无（直接读取） | 仅记录，无来源 | 不支持更新 |
| 存量迁移 | 扫描工具目录 + 公共目录 | 同一下载器（判定 remote 时）| 支持 | 判定为 remote 时支持 |

## 8. 核心架构原则

1. **最小权限**：技能只存在于私有目录中，仅通过链接投射到用户指定的工具目录，其他工具无法读取
2. **完全自研**：不调用 `npx skills` 的任何命令，下载、安装、更新、卸载全部由 Rust 后端自主实现
3. **单一数据源**：私有中央仓库是技能的最终存储位置，所有 AI 工具目录中的链接指向它
4. **不做过度设计**：local 区扁平化、命名冲突走覆盖/重命名交互，不引入无谓的复杂度

## 9. 存量兼容策略

| 场景 | 处理方式 |
|------|---------|
| 平时行为 | 只管理 `~/.skillsage/`，不扫描公共目录和工具目录 |
| 分发冲突（非我们创建的条目） | 弹窗三选一：跳过该工具 / 接管（移入中央仓库重建链接）/ 取消 |
| 迁移入口（管理页提供） | 扫描工具目录 + 公共目录，识别条目类型，接管实体后建链接 |
| 接管对象 | 一律接管实体（中央仓库中的实际内容），不接管链接 |
| 归属判定 | 查 npx lock 能匹配来源 → remote；不能 → local |
| 迁移方式 | 从公共目录接管采用**移动**，明确告知用户"npx 将不再管理该技能" |
| 未知来源链接 | 扫描结果中标记，提供"删除链接"操作供用户自行处置 |

## 10. 商店数据源方案

### 搜索接口

`https://skills.sh/api/search?q=<关键词>` —— 无需认证，返回结构化 JSON。包含 id、name、source、installs 等字段。

### 详情接口

`https://www.skills.sh/<作者>/<仓库>/<技能名>` —— 直接抓取 HTML 页面提取字段。返回技能描述（Summary）、SKILL.md 正文、所属 Topic、安装量、GitHub Stars、首次出现时间、仓库链接、安全审计结果（Gen Agent Trust Hub / Socket / Snyk 的 Pass/Warn 状态）、相关技能推荐。

### 排行榜

当前实现直接抓取 skills.sh 的 All Time / Trending / Hot 页面并解析排行榜卡片；不依赖尚未公开或需要认证的内部 JSON 端点。页面结构变化时需通过回归测试及时调整解析器。

## 11. 商店交互要点

- **会话级缓存**：排行榜数据在软件运行期间有效，关闭即清，提供"更新"按钮强制刷新
- **搜索不缓存**：每次实时请求
- **工具检测**：启动时异步检测一次，检测结果驻留内存，用于详情页默认勾选已检测到的工具
- **默认勾选逻辑**：只勾选已检测到已安装的工具，未检测到的不默认勾选
- **安全审计展示**：详情页展示三家审计结果；Warn 状态在安装确认时醒目标注
- **商店聚合**：同一仓库的多个技能在列表中合并展示（"+N more from" 风格）
- **不按工具过滤商店内容**：所有技能对所有工具可装，勾选时由用户决定分发给谁

## 12. 跨设备同步设计

### 导出格式：JSON 清单

导出的本质是一份远程技能的清单，不含技能内容本身。携带描述、版本、分发记录等元数据，让导入预览页能展示清晰内容。

### 导入流程

选择 JSON 文件 → 解析校验 → 预览页展示技能清单 → 用户勾选要导入的技能 → 逐个检查清单中的 distributedTo 在新设备上的工具检测结果：

- 检测到 → 直接分发
- 未检测到 → 弹窗让用户选"跳过"或"坚持分发"（自动建目录）；批量决策，不逐技能弹窗

### local 技能处理

local 技能完全不进入同步清单——它没有远端源，无法在新设备重建，明确排除。

## 13. 卸载应用时的清理

卸载时弹出确认弹窗，让用户选择：
- **清理全部**：删除中央仓库 + 遍历 lock 删除所有已建链接，AI 工具回到未装过这些技能的状态
- **保留技能**：保留中央仓库和现有链接，只清理 lock、设置等管理数据（技能在 AI 工具中仍可用，但不再由 SkillSage 管理；删除中央仓库会使链接失效）
