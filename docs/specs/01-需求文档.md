# Skillsage 需求文档（最终版）

> 2026-08-20 更新：第 3、4、5、8、9、11、12、13 节已改写，反映"单一共享目录"重构（详见
> `docs/memory/decisions.md` 对应决策与 `docs/memory/do-not-use.md` 中被放弃的旧方案）。

## 1. 项目定位

**Skillsage** —— 面向 Windows 和 macOS 的 AI Agent 技能管理器。用户可以从 skills.sh 浏览/搜索技能、从 GitHub URL 直接安装、或从本地导入，直接安装到一个所有 AI 工具共享的公共技能目录（`~/.agents/skills/`）。支持版本管理、更新回退、跨设备同步、存量技能采纳。

## 2. 技术栈

| 层 | 技术 |
|----|------|
| 桌面框架 | Tauri 2 |
| 前端 | React + shadcn/ui + pnpm |
| 后端 | Rust（核心逻辑完全自研，不依赖 `npx skills`） |
| 后端关键依赖 | reqwest、tokio、serde、serde_yaml、scraper、keyring、blake3、thiserror、dirs、tracing |

## 3. 安装目标

技能直接安装到唯一的共享公共目录：

| 平台 | 公共目录 |
|------|---------|
| Windows / macOS | `~/.agents/skills/<技能名>/` |

不再有"分发"这一步——技能内容本身就落在这个目录里，扁平结构，不按作者或来源分子目录。任何读取该目录的 AI 工具都能立即看到已安装的技能，无需 Skillsage 逐个建链接。**不支持复制到多个位置**：每个技能名在该目录下只有一份真实内容。

## 4. 工具兼容性说明

Skillsage 不再检测、区分或注册具体的 AI 工具。历史上（Phase 1-7）产品曾维护一份"首发支持工具"清单（Claude Code、Cursor、GitHub Copilot、OpenAI Codex CLI、OpenCode），并把 `.agents/skills/` 这类通用共享目录列为"不符合最小权限原则，明确不支持"。

这一判断已被推翻：实测发现多款 AI 工具（不止 Amp）本身就会读取 `~/.agents/skills/` 或类似的共享位置，与 Skillsage 是否为它们单独建链接无关——"只对显式选中的工具暴露技能"这一隔离承诺在实践中无法兑现。继续维护面向多个私有目录的符号链接/目录联接分发机制，只是在为一个不成立的保证增加复杂度和攻击面。因此产品转为直接使用这个已经被多个工具共享的公共目录，不再尝试逐工具隔离，也不再提供自定义工具注册。

## 5. 公共目录与本地管理数据结构

```
~/.agents/skills/                ← 公共目录：所有技能的真实内容，扁平结构，不区分来源
├── <技能名>/
│   ├── SKILL.md    ← 核心文件（必需）
│   ├── scripts/    ← 可选
│   ├── references/ ← 可选
│   └── assets/     ← 可选
└── ...

~/.skillsage/                    ← Skillsage 自己的管理数据，不含任何技能内容
├── lock/
│   ├── skill-lock.json  ← 全局锁文件（来源、版本指针历史、hash）
│   └── snapshots/       ← 更新时的旧版本快照，按技能名寻址（不再按作者分子目录）
├── settings.json         ← 代理等应用设置
└── tmp/                   ← 临时目录（安装/更新时使用）
```

## 6. 产品功能清单

| 功能 | 说明 |
|------|------|
| 技能商店浏览 & 搜索 | 搜索走 `api/search` JSON 接口，排行榜走 `skills.sh` 页面 |
| 技能详情 | 抓取 `www.skills.sh/<作者>/<仓库>/<技能名>` HTML 页面提取字段 |
| 技能安装（从商店） | 自研下载器，从 GitHub 拉取技能内容直接写入公共目录 |
| 技能安装（GitHub URL） | 解析 URL 为 owner/repo/skillPath，复用商店下载逻辑 |
| 技能安装（本地导入） | 自动解析 SKILL.md frontmatter，校验失败则提示用户 |
| 安装冲突处理 | 目标名称已被未跟踪的内容占用时，弹窗三选一：跳过 / 备份后继续（原内容改名保留）/ 取消 |
| 检查更新 | 用户手动触发，基于 lock 中的 source 去 GitHub 拉取最新版，对比 hash |
| 技能更新 | 备份当前版本（快照 + 版本指针 append）→ 原子替换 → 更新 lock |
| 版本回退 | 优先从 GitHub 拉取指定 commit 内容，不可得时走本地快照兜底，都失败则报错 |
| 技能卸载 | 从公共目录删除该技能文件夹 + 删除记录，不做回滚，失败项可重试 |
| 本地导入 | 支持目录/单文件，自动解析 frontmatter，以 `name` 为权威标识 |
| 跨设备同步 | 导出包含远程技能记录和非敏感设置的 JSON 同步数据，新设备按需重新拉取 |
| 技能采纳 | 扫描公共目录中已存在但未被 Skillsage 记录的技能文件夹，原地登记，不移动文件 |
| 设置 | GitHub Token 配置（本地加密存储，不参与同步）、代理配置 |

## 7. 安装来源对比

| 来源 | 前置识别 | 下载逻辑 | lock 记录 | 更新/回退 |
|------|---------|---------|-----------|----------|
| 商店 | skills.sh 搜索/排行榜 | 同一下载器 | 支持 | 支持 |
| GitHub URL | 解析 owner/repo/skillPath | 同一下载器 | 支持 | 支持 |
| 本地导入 | 文件系统定位 SKILL.md | 无（直接读取） | 仅记录，无来源 | 不支持更新 |
| 存量采纳 | 扫描公共目录 | 不下载，直接登记原地内容 | 尽力恢复远程来源，恢复失败则记为本地来源 | 恢复远程来源成功时支持 |

## 8. 核心架构原则

1. **单一公共目录**：所有技能的真实内容只存在于 `~/.agents/skills/` 这一个位置，没有私有副本，没有分发链接——这既是唯一数据源，也是所有 AI 工具的读取位置（第 4 节已说明为何放弃"仅对选中工具暴露"的旧原则）
2. **完全自研**：不调用 `npx skills` 的任何命令，下载、安装、更新、卸载全部由 Rust 后端自主实现
3. **管理数据与内容分离**：`~/.skillsage/` 只保存锁文件、快照和设置，从不保存技能内容本身，删除它不会影响公共目录中已安装的技能
4. **不做过度设计**：命名冲突走跳过/备份后继续的交互，不引入无谓的复杂度；采纳流程不移动文件，文件夹名即技能名，不做去重算法

## 9. 存量兼容策略

| 场景 | 处理方式 |
|------|---------|
| 平时行为 | 只管理 `~/.skillsage/` 的锁文件；采纳功能才会读取公共目录，且是用户显式触发的只读扫描 |
| 安装冲突（目标名称被未跟踪内容占用） | 弹窗三选一：跳过 / 备份后继续（原内容改名为 `<名称>.skillsage-backup-<时间戳>` 保留，不删除）/ 取消 |
| 采纳入口（"采纳技能"页提供） | 扫描公共目录，列出未被跟踪的文件夹；有效的（含可解析 SKILL.md）可勾选批量登记 |
| 采纳方式 | 原地登记，**不移动、不复制**文件；文件夹名即为技能名，不采用 SKILL.md 中可能不同的声明名称 |
| 归属判定 | 尝试匹配其他工具自身的锁文件格式恢复远程来源；恢复后会重新拉取该 commit 校验内容哈希一致才采信，否则记为本地来源 |
| 无效条目 | 只做展示和原因说明（例如缺少有效 SKILL.md），不提供删除操作——公共目录里的链接或其他内容不属于 Skillsage 创建，是否清理不由本应用判断 |

## 10. 商店数据源方案

### 搜索接口

`https://skills.sh/api/search?q=<关键词>` —— 无需认证，返回结构化 JSON。包含 id、name、source、installs 等字段。

### 详情接口

`https://www.skills.sh/<作者>/<仓库>/<技能名>` —— 直接抓取 HTML 页面提取字段。返回技能描述（Summary）、SKILL.md 正文、所属 Topic、安装量、GitHub Stars、首次出现时间、仓库链接、安全审计结果（Gen Agent Trust Hub / Socket / Snyk 的 Pass/Warn 状态）、相关技能推荐。

### 排行榜

当前实现直接抓取 skills.sh 的 All Time / Trending / Hot 页面并解析排行榜卡片；不依赖尚未公开或需要认证的内部 JSON 端点。页面结构变化时需通过回归测试及时调整解析器。

## 11. 商店交互要点

- **会话级缓存**：排行榜数据在软件运行期间有效，关闭即清，提供"更新"按钮强制刷新
- **搜索不缓存**：每次实时请求
- **安全审计展示**：详情页展示三家审计结果；Warn 状态在安装确认时醒目标注
- **商店聚合**：同一仓库的多个技能在列表中合并展示（"+N more from" 风格）
- **安装即完成**：详情页只有一个"开始安装"动作，没有工具勾选步骤；若目标名称冲突则弹出安装冲突处理（见第 9 节）

## 12. 跨设备同步设计

### 导出格式：JSON 同步数据

导出的本质是一份可在设备间迁移的同步数据，不含技能内容本身。它包含远程技能描述、版本、显示模式、主题色和代理设置。GitHub Token 属于本机敏感凭据，不进入同步数据。导出时由用户选择文件保存位置。

### 导入流程

选择 JSON 文件 → 解析校验 → 预览页展示同步数据 → 用户勾选要导入的技能和应用设置 → 逐个重新拉取选中技能的记录 commit 并安装到公共目录。不再有"检测工具/决定分发给谁"这一步。

### local 技能处理

local 技能完全不进入同步数据——它没有远端源，无法在新设备重建，明确排除。

## 13. 卸载应用时的清理

卸载时弹出确认弹窗，让用户选择：
- **删除技能与数据**：从公共目录中删除 Skillsage 安装的**每一个技能文件夹**（真实文件，不是链接）+ 删除 `~/.skillsage/` 全部管理数据。所有读取公共目录的 AI 工具会**立即、同时**失去这些技能，且不可恢复；未被 Skillsage 跟踪的文件夹不受影响。这比旧模型（删除的是链接）破坏性大得多，需要在确认文案中说清楚。
- **保留并停止管理**：只删除 `~/.skillsage/`（锁文件、快照、设置），公共目录中的所有文件完全不动。这比旧模型更安全——旧模型仍需要保留链接指向的私有副本才能让技能继续可用；新模型下"保留"意味着真正意义上什么都不碰。
