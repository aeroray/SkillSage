# Skillsage 前端结构

> 2026-08-20 更新：`features/tools/`、`features/migrate/`、`components/common/ToolSelection.tsx`
> 已删除，新增 `features/adopt/` 和共享的 `PathConflictDialog.tsx`。详见 `docs/memory/decisions.md`。

## 一、顶层划分

```
src/
├── main.tsx                  # 入口（挂载 React）
├── App.tsx                   # 路由挂载
│
├── app/                      # 应用级：路由、布局、全局 Provider
├── pages/                    # 页面级：路由组件，只做组合与排版
├── features/                 # 领域逻辑：数据获取、状态、类型（核心）
├── components/               # 共享 UI：shadcn 组件 + 业务共享组件
├── lib/                      # 通用工具：invoke 封装、格式化
├── types/                    # 跨领域共享类型
└── index.css                 # Tailwind v4 CSS-first 全局样式与 token
```

**核心思路与后端一一对应**：
- `pages/` 相当于后端的 `commands/` 薄壳（只做组合）
- `features/` 相当于 `core/` 领域逻辑（真正的业务）
- `lib/` 和 `components/ui/` 相当于基础设施

前后端心智模型统一："按领域找文件"。

## 二、features/ —— 领域逻辑层（前端的心脏）

每个领域一个目录，内部统一为四个文件，职责边界固定：

### skills/ — 技能管理领域

| 文件 | 职责 |
|------|------|
| `api.ts` | 调 Tauri command 的薄封装（参数 + 返回类型） |
| `types.ts` | 技能相关的 TS 类型（对齐后端结构），含共享的 `PathConflict`/`ConflictDecision` |
| `hooks.ts` | useSkillsList / useSkillInstall / useInstallConflictCheck |
| `selectors.ts` | 纯函数：过滤、排序、分组（可单测） |

### store/ — 商店领域

| 文件 | 职责 |
|------|------|
| `api.ts` | search / leaderboard / detail |
| `types.ts` | 商店侧数据结构 |
| `hooks.ts` | useSearch / useLeaderboard / useDetail |
| `cache.ts` | 会话级缓存策略（排行榜 staleTime 控制） |

### import/ — 本地导入领域

| 文件 | 职责 |
|------|------|
| `api.ts` | 导入命令封装 |
| `types.ts` | 导入相关类型 |
| `hooks.ts` | useImport |

### adopt/ — 存量技能采纳领域

| 文件 | 职责 |
|------|------|
| `api.ts` | 扫描 / 采纳命令封装（沿用后端 `scan_migrate`/`execute_migrate` command 名） |
| `types.ts` | `AdoptableItem`/`AdoptScanResult`/`AdoptSelection`/`AdoptResult` |
| `hooks.ts` | useAdoptScan / useAdoptExecute |

### sync/ — 跨设备同步领域

| 文件 | 职责 |
|------|------|
| `api.ts` | 导出 / 导入命令封装 |
| `types.ts` | 同步相关类型（不再含每技能的工具勾选状态） |

### settings/ — 设置领域

| 文件 | 职责 |
|------|------|
| `api.ts` | 设置读写命令封装 |
| `types.ts` | 设置相关类型 |
| `hooks.ts` | useSettings |

**职责约定**：
- `api.ts` 只做 invoke 封装，不含业务逻辑（薄壳，对应后端 commands）
- `hooks.ts` 封装数据获取与操作调用，页面组件只消费 hooks，不直接碰 invoke
- `types.ts` 定义领域内类型，跨领域共享的放全局 `types/`
- `selectors.ts` 这类纯函数独立出来，方便 vitest 单测（过滤/排序/分组逻辑是最值得测的部分）

| 组件 | 说明 |

### import/ — 本地导入

| 组件 | 说明 |

### adopt/ — 存量技能采纳

| 组件 | 说明 |

## 四、components/ 与 lib/

### components/ui/

shadcn 生成组件（button/dialog/checkbox/select/tabs/card/badge/toast/tooltip/skeleton/table/scroll-area/accordion/dropdown-menu 等），保持原样，不手改业务逻辑进去。

### components/common/ — 业务共享组件

| 组件 | 说明 |
|------|------|
| `EmptyState.tsx` | 空态引导（商店无网络 / 管理页无技能） |
| `PathConflictDialog.tsx` | 共享的安装冲突弹窗（跳过 / 备份后继续 / 取消），商店安装、本地导入、GitHub URL 安装共用同一个组件 |
| `ErrorBanner.tsx` | 统一错误提示 |

### lib/

| 文件 | 职责 |
|------|------|
| `tauri.ts` | invoke 统一封装（错误规范化、Promise 化） |
| `format.ts` | 安装量/时间格式化 |
| `cn.ts` | className 合并（shadcn 默认提供） |

## 五、状态管理方案

| 数据类型 | 方案 | 理由 |
|---------|------|------|
| 服务端状态（技能列表、搜索结果、排行榜、采纳扫描结果） | feature hooks + 显式请求状态 | 页面规模较小，hooks 管理 loading/error/retry；排行榜、已安装列表、采纳扫描均使用模块级会话缓存 |
| 全局共享状态（主题） | zustand | 持久化到本地 |
| 局部 UI 状态（弹窗开关、筛选器值） | 组件内 `useState` | 不跨页面，不提升 |

**事件流约定**：Tauri 的进度事件（安装阶段变化）由 features 的 hooks 统一订阅，转成前端状态后下发给页面组件。页面不直接监听 Tauri 事件，保持"页面只依赖 hooks"的单向数据流。

## 六、路由结构

```
/                     → 重定向到 /skills
/store                → StorePage（商店）
/store/:skillId      → SkillDetailDialog（详情弹窗覆盖在商店上）
/skills               → SkillsPage（管理页）
/adopt                → AdoptPage（存量技能采纳）
/settings             → SettingsPage（设置）
```

左侧导航栏固定展示四个入口，顺序为：我的技能、技能商店、采纳技能、设置。采纳页面只在用户主动打开时扫描公共目录。

## 七、文件命名约定

- 组件 / 页面：`PascalCase.tsx`（`SkillCard.tsx`）
- 纯逻辑 / hooks / 类型：`camelCase.ts`（`api.ts`、`useSkillsList.ts`）
- 目录名：小写单词（`features/skills`、`pages/store`）

约定简单、一眼可辨，避免团队内命名风格分裂。
