# Skillsage 设计规范

## 一、设计语言定位

shadcn/ui 偏简约的设计系统，底层的 Radix 组件无样式、Tailwind 控制一切。在此基础上，简约风格的核心约束：

- **色彩克制**：主色只用于按钮、链接、激活态、关键高亮，其余全部用 neutral 灰阶表达层次
- **间距宽松**：组件之间、区块之间的留白给足，不要让信息挤在一起
- **边框弱化**：用 `border-muted` 或 `border-transparent` 替代实线边框，靠阴影和背景色区分层级
- **字体层级清晰**：字号和字重传递信息层级，不需要额外装饰

## 二、主题配色

**外观模式**：深色 / 浅色 / 跟随系统（三种）。外观模式只改明暗，主题配色只改主色。

### 方案一：Slate Blue（静谧蓝）—— 首选推荐

| 角色 | 浅色模式 | 深色模式 |
|------|---------|---------|
| primary | `#3B82F6` → 深蓝 | `#60A5FA` → 亮蓝 |
| primary-foreground | `#FFFFFF` | `#0F172A` |

偏冷的灰蓝色，视觉上冷静、专业，和大量中性色搭配时非常和谐。

## 三、圆角系统

整个应用的圆角不超过 3 个层级，每个层级有明确的语义归属：

| 层级 | CSS 变量 | 值 | 适用对象 |
|------|---------|-----|---------|
| 基础圆角 | `--radius` | `0.5rem`（8px） | 按钮、输入框、选择器、标签、下拉菜单、Toast |
| 容器圆角 | `--radius-lg` | `0.75rem`（12px） | 卡片、弹窗（Dialog / Sheet）、侧边栏、技能卡片 |
| 无圆角 | `--radius-none` | `0` | 进度条、分割线、Tab 底栏、表格行 |

**严格规则**：
- 所有组件必须使用 CSS 变量，禁止硬编码 `rounded-[6px]`、`rounded-[10px]` 等
- 基础圆角之外不引入第 4 个值
- 按钮统一用 `rounded-md`（映射到 `--radius`），`rounded-full`（胶囊形）只在特定场景使用（如数量徽标 Badge、Tag 的清除按钮），且必须全局统一

## 四、像素规范

所有尺寸值必须为 **4 的倍数**（即 Tailwind 默认的 `0.25rem` 步进），禁止出现奇数 px。

| 场景 | 推荐做法 | 禁止做法 |
|------|---------|---------|
| 间距 | Tailwind 内置间距 `p-1`(4px) ~ `p-6`(24px) | `p-3.5`(14px)、`px-[13px]` |
| 尺寸 | `w-8`(32px)、`h-10`(40px) | `w-[33px]`、`h-[27px]` |
| 圆角 | 已由 CSS 变量统一 | `rounded-[5px]`、`rounded-[7px]` |
| 边框 | `border`(1px)、`border-2`(2px) | `border-[1.5px]` |
| 图标尺寸 | `h-4 w-4`(16px)、`h-5 w-5`(20px) | `h-[18px]` |

**例外规则**：仅文本行高（`leading-tight` 等）不受此限制，因为字体渲染本身就有亚像素。除此之外的所有尺寸、间距、内外边距一律遵守 4px 步进。

## 五、阴影层级

| 层级 | 值 | 适用对象 |
|------|-----|---------|
| 浅阴影 | `shadow-sm` | 卡片（默认态）、输入框、下拉菜单 |
| 深阴影 | `shadow-lg` | 模态框、弹窗、Sheet 侧边栏、通知 |
| 无阴影 | `shadow-none` | 侧边栏面板、表格、按钮、导航栏 |

- 不引入 `shadow-md`、`shadow-xl`、`shadow-2xl`
- 阴影在深色模式下透明度降低（`dark:shadow-sm dark:shadow-black/30`）

## 六、字体与排版

| 角色 | 字号 | 字重 | 行高 | 使用场景 |
|------|------|------|------|---------|
| 页面标题（H1） | `text-2xl`(24px) | `font-semibold` | 标题栏、页面标题 |
| 区块标题（H2） | `text-xl`(20px) | `font-semibold` | 作者组名、弹窗标题 |
| 卡片标题 | `text-base`(16px) | `font-medium` | 技能名、工具名 |
| 正文 | `text-sm`(14px) | `font-normal` | 描述文字、列表内容 |
| 辅助文字 | `text-xs`(12px) | `font-normal` | 安装量、版本号、标签、时间戳 |

**字体栈**：系统字体，不额外加载

```css
font-family: -apple-system, BlinkMacSystemFont, 'Segoe UI', 'PingFang SC',
  'Microsoft YaHei', 'Helvetica Neue', sans-serif;
```

## 七、颜色使用原则

| 语义角色 | 使用场景 | 禁止场景 |
|---------|---------|---------|
| `primary` | 主按钮、链接、激活态 Tab、选中态 | 背景色、卡片底色、分割线 |
| `muted` | 辅助文字、禁用态、占位符 | 标题、正文 |
| `destructive` | 删除按钮、卸载确认、Warn 审计标记 | 关闭按钮、取消操作 |
| `success` / `green` | 安装成功、审计 Pass、分发完成 | 普通按钮 |
| `warning` / `amber` | 审计 Warn、更新可用 | 错误提示 |
| `accent` | hover 高亮、选中行背景 | 按钮、标题 |

**严格规则**：
- `text-muted-foreground` 只能用于辅助信息，禁止用于正文标题
- `bg-primary` 只能用于主按钮和激活态背景，禁止用于卡片背景
- 状态色（success/warning/destructive）在浅色和深色模式下是同一套色相，仅明度变化

## 八、组件级规范

| 组件 | 圆角 | 内边距 | 阴影 | 特殊规则 |
|------|------|--------|------|---------|
| Button（主） | `--radius` | `h-9 px-4` | 无 | 禁用态用 `opacity-50`，不用改颜色 |
| Button（图标） | `--radius` | `h-9 w-9` | 无 | 只用图标，无文字 |
| Card | `--radius-lg` | `p-4` | `shadow-sm` | 深色模式 `bg-card` |
| Dialog | `--radius-lg` | `p-6` | `shadow-lg` | 遮罩用 `bg-black/50` |
| Input | `--radius` | `h-9 px-3` | 无 | focus 态用 `ring-1 ring-primary` |
| Badge | `--radius` | `px-2 py-0.5` | 无 | 字号统一 `text-xs` |
| Table Row | 无 | `h-10` | 无 | hover 时 `bg-muted/50` |

## 九、图标规范

- **图标库**：Lucide（shadcn 生态标配，线条风格，最契合简约调性）
- **默认尺寸**：`h-4 w-4`（16px），所有按钮图标、列表图标、标签图标统一
- **大尺寸**：`h-5 w-5`（20px），仅限导航栏、空态大图标、弹窗标题图标
- **颜色**：图标颜色继承父元素文本色，不单独指定（除非是状态图标如 success/warning）

## 十、垂直对齐规范

**核心原则**：同一行/同一容器内的所有元素，视觉重心必须在同一条水平线上。

| 问题场景 | 错误写法 | 正确做法 |
|---------|---------|---------|
| 图标 + 文字同行 | 图标用 `align-middle` 或不管 | `flex items-center`，图标和文字放在同一个 flex 容器中 |
| Badge + 文字同行 | Badge 的 `py` 导致偏下 | 外层容器统一 `items-center`，Badge 用 `inline-flex items-center` 包裹 |
| 按钮内的图标 + 文字 | 图标单独放，文字单独放 | 按钮内统一用 `<span className="inline-flex items-center gap-1.5">` 包裹 |
| 表格行内多列 | 列内元素各自上下浮动 | 表格行统一 `h-10`，列内内容用 `flex items-center` |
| 输入框 + 后缀按钮 | 按钮在输入框外手动对齐 | 用 `Input` 组件的 `rightSection` 或 `relative` + `absolute right-0` + `flex items-center` |

**严格规则**：
- **禁止**使用 `vertical-align` 属性。所有对齐需求一律用 `flex items-center` 解决
- 同一行中如果有多个元素（图标、文字、标签、按钮），最外层必须有一个 `flex items-center` 容器包裹，不允许各自独立浮动
- 图标组件（Lucide）默认带 `stroke-width` 和 `viewBox` 导致的视觉偏移，用 `flex items-center justify-center` 包裹后整体居中，不单独调整图标的 `margin` 或 `translate`
- 文本行高导致文字在一行内偏上或偏下，用 `leading-none` 或 `leading-tight` 统一修正，不通过 `padding` 或 `margin` 微调

**最简检查方法**：开发时在任何一行/一列上选中所有元素，检查它们的 `offsetTop` 是否一致。不一致说明对齐有问题。

## 十一、组件使用优先级

**核心原则**：优先使用 shadcn 组件，其次使用 Radix 原语，最后才用原生 HTML 标签。

| 优先级 | 来源 | 示例 | 说明 |
|--------|------|------|------|
| 1 | shadcn/ui 组件 | `Button`、`Dialog`、`Sheet`、`Select`、`Input`、`Checkbox`、`Switch`、`Tabs`、`Card`、`Badge`、`Toast`、`Tooltip`、`Skeleton`、`Table`、`ScrollArea`、`Accordion`、`DropdownMenu` | shadcn 有现成的，直接用，不要自己封装 |
| 2 | 原生 HTML 标签 | `div`、`span`、`p`、`h1~h3`、`section`、`header`、`main` | 布局容器、文本、语义化结构，无法避免，正常使用 |
| 3 | 原生 HTML 交互标签 | `<button>`、`<input>`、`<select>` | **禁用**——shadcn 都有对应的组件封装，原生交互标签不参与样式系统 |

### 关于滚动条（ScrollArea）

shadcn 有 `ScrollArea` 组件（基于 Radix ScrollArea），提供统一的滚动条外观，在不同操作系统上保持一致。

**所有需要滚动的内容区域都必须用 `ScrollArea` 包裹**，禁止使用浏览器原生 `overflow-auto` 的滚动条：
- 管理页技能列表 → `ScrollArea`
- 商店搜索列表 → `ScrollArea`
- 弹窗内长内容 → `ScrollArea`
- 详情页的 SKILL.md 正文预览 → `ScrollArea`
- 设置页集群 → `ScrollArea`

**唯一例外**：`textarea` 和 `Dialog` 的 `overflow` 由 shadcn 组件内部处理，不需额外包裹。

**实施方式**：Code Review 时如果看到 `overflow-auto` 或 `overflow-y-auto`，直接打回。只有 `ScrollArea` 一种写法。

## 十二、动画时长

| 场景 | 时长 | 缓动 |
|------|------|------|
| hover / active | 150ms | `ease-out` |
| 弹窗出现 / 消失 | 200ms → 150ms | `ease-out` → `ease-in` |
| 折叠展开 | 200ms | `ease-in-out` |
| 页面切换 / 列表过滤 | 300ms | `ease-out` |

- 不使用弹跳（spring）、旋转、缩放放大等花哨动效
- 动效一律通过 Tailwind 的 `transition-all duration-150` 等类名控制，不写自定义 keyframes

## 十三、空态与加载态

- **空态页不是"空白"，而是用简约的图标 + 一句话说明 + 一个操作按钮**，引导用户做下一步
- **加载态不要用旋转的 loading spinner**，建议用**骨架屏（Skeleton）**，shadcn 自带 `Skeleton` 组件，对于列表页和卡片页来说，骨架屏的视觉噪声远小于 spinner

## 十四、实施方式

以上规范通过两个途径落地：

1. **Tailwind 配置**：Tailwind v4 使用 `src/index.css` 的 CSS-first `@theme inline` 锁定颜色、圆角和阴影 token；不再维护 v3 的 `tailwind.config.ts` / PostCSS 配置
2. **Code Review 检查项**：合并请求时检查三点——① 是否有硬编码的圆角/间距值 ② 是否有奇数 px ③ 颜色语义使用是否正确
