# Skillsage 生命周期状态机

> 2026-08-20 更新：随"单一共享目录"重构，技能不再有"已分发/未分发"这一维度，
> "调整分发时序"整节删除。详见 `docs/memory/decisions.md`。

## 一、技能的状态模型

一个技能在系统中存在以下主状态：

```
                         ┌─────────────┐
                         │  未安装      │
                         └──────┬──────┘
                                │ 安装
                                ▼
                         ┌─────────────┐
                         │  已安装      │◄──────────┐
                         │ (公共目录)   │           │ 更新/回退
                         └──────┬──────┘───────────┘
                                │ 卸载
                                ▼
                         ┌─────────────┐
                         │  已卸载      │
                         └─────────────┘
```

"已安装"直接对应公共目录（`~/.agents/skills/<name>/`）中存在这个文件夹并被 lock 记录跟踪——不再有中间的"分发"步骤，安装完成即所有读取该目录的 AI 工具都能看到它。

横向正交维度——**版本状态**（`up_to_date` / `update_available`）和**操作状态**（`installing` / `updating` / `rolling_back` / `uninstalling`），叠加在上述主状态之上，由前端 UI 呈现。

## 二、安装时序

### 完整流程

```
1. 校验入参（skillId 合法性）
2. 创建临时目录 ~/.skillsage/tmp/<pid>-<纳秒>/
3. 解析 skillId → owner/repo/skillPath（来源不同解析方式不同）
4. 请求 GitHub 获取仓库文件树，定位技能目录
5. 下载技能目录全部文件到临时目录
6. 解析 SKILL.md frontmatter 并校验
   → 失败：清理临时目录，结束（此刻未触碰任何真实位置）
7. 读 lock，检查两层名称冲突：
   a. 是否已有 lock 记录跟踪同名技能（NameConflict）→ 中止，这不是"路径被占用"，
      是"我们自己已经装过了"，需要用户先卸载或换名，不进入接管流程
   b. 公共目录中该名称对应的路径是否被未跟踪的内容占用（InstallConflict）→
      按调用方传入的 conflict_action 处理：
        - 未传 / 非 "takeover" → 中止，返回冲突详情供前端展示跳过/备份后继续/取消
        - "takeover" → 把占用内容改名为 `<名称>.skillsage-backup-<时间戳>` 保留，
          从不删除、也不原地接管对方的内容
8. 原子落库：移动临时目录 → ~/.agents/skills/<技能名>/
   → 失败：撤销上一步的改名接管（如果做了），清理临时目录
9. 写入 lock（source、skillPath、commit、hash、installedAt）
   → 失败：删除刚落库的目录，撤销接管
10. 完成
```

### 回滚关键设计

**第 6 步把一切可能失败的校验前置到了临时目录**——落库之前所有可能失败的校验都在临时目录完成。落库后只剩"写 lock"一个风险点，失败时直接删除刚落库的目录、撤销接管即可。回滚路径最短——比旧模型更短，因为不再有"逐工具建链接"这一整层可能失败的操作。

## 三、检查更新（只读操作）

```
1. 读 lock，取 source + skillPath + currentHash
2. 请求 GitHub 获取技能目录在最新 commit 下的内容 hash
3. 对比：相同 → 无更新；不同 → 有更新，返回新版信息
```

- **只读操作**，可与其他读操作并发
- UI 层保证它和写操作不同时触发（如更新按钮在操作中禁用）

## 四、更新时序

### 完整流程

```
1. 加写锁
2. 读 lock，确认技能已安装且是 remote 来源（local 不支持更新）
3. 下载最新版本到临时目录（复用安装的第 3~5 步）
4. 解析校验
   → 失败：清理临时目录，中止，系统保持原状
5. 备份当前版本（顺序固定，不能颠倒）：
   a. 复制当前内容 → ~/.skillsage/lock/snapshots/<技能名>/<hash>/（按内容哈希寻址，
      不再按作者分子目录）
   b. 将当前 commit + 时间戳 append 到 lock 的 versionHistory
6. 原子替换：临时目录内容 → 公共目录中的技能文件夹（若与私有临时目录不同卷，
   退化为递归复制 + 删除源）
7. 更新 lock：currentVersion = 新 commit、currentHash = 新 hash
8. 完成——所有读取公共目录的 AI 工具立即看到新内容，不需要对它们做任何操作
```

### 为什么顺序重要

**第 5 步的备份必须发生在第 6 步替换之前**——先快照后替换，快照里的才是"旧版本"。第 6 步失败时，用第 5 步的快照 + 已 append 的版本指针恢复原状；如果第 5 步先于快照就替换，旧内容就丢了。这是更新流程最容易写错的地方。

## 五、回退时序

### 完整流程

```
1. 加写锁
2. 用户从 versionHistory 选择目标版本
3. 尝试从 GitHub 拉取该 commit 的技能内容 → 临时目录
   → 成功：继续
   → 失败（force push / 删库导致 commit 不可得）：
       检查本地快照 → 有则从快照恢复内容到临时目录
                     → 无则报错中止（明确告知原因）
4. 解析校验
5. 备份当前版本（同更新：先快照，再 append 版本指针）
6. 原子替换公共目录中的技能文件夹
7. 更新 lock（currentVersion/currentHash 改为回退目标）
8. 完成
```

### 与更新的关系

回退与更新共享第 5~7 步的骨架，差异只在第 3 步的内容来源（GitHub 指定 commit vs 最新 commit）——实现上回退直接调用更新的核心函数。

## 六、卸载时序

### 完整流程

```
1. 加写锁
2. 读 lock，定位该技能在公共目录中的路径
3. 删除公共目录中的技能文件夹（真实内容，不是链接）
4. 删除对应快照（local:// 来源的技能没有快照，跳过）
5. 删除 lock 记录
6. 完成
```

### 这是新模型里最容易被低估的一步

旧模型的卸载删的是链接——可随时通过"调整分发"重建，中央仓库里的真实内容毫发无损。新模型没有这层缓冲：第 3 步删除的就是所有 AI 工具实际读取的那份内容，操作完成的瞬间，每一个配置了该公共目录的工具都会同时失去这个技能。UI 侧的确认文案必须把这一点说清楚，不能沿用旧模型"只是断开链接"式的轻描淡写。

### 失败处理策略

**不做回滚，只做重试**。卸载是幂等操作——文件夹已删的不会恢复，重试时会在文件夹已不存在的情况下继续删 lock 记录。对文件删除失败（如文件被占用）的错误，明确提示用户路径，让其手动处理后重试。

## 七、并发控制与失败处理统一原则

### 并发控制

| 操作类型 | 是否加锁 | 说明 |
|---------|---------|------|
| 安装 | ✅ 写锁 | |
| 更新 | ✅ 写锁 | |
| 回退 | ✅ 写锁 | |
| 卸载 | ✅ 写锁 | |
| 导入 | ✅ 写锁 | |
| 采纳 | ✅ 写锁 | |
| 列表/详情 | ❌ 不加锁 | 读操作可并发 |
| 检查更新 | ❌ 不加锁 | 只读 |
| 扫描采纳候选 | ❌ 不加锁 | 只读 |

所有写操作经一把全局异步锁串行化。

### 四条失败处理原则

1. **先校验后落库** —— 一切可能失败的校验都在临时目录完成，未触碰真实位置前失败就是"清理临时目录"
2. **回滚只撤销本次操作已产生的副作用** —— 接管的内容改名恢复、刚落库的目录删掉，不做超出本次范围的补偿
3. **安装冲突的接管可逆** —— 改名保留而非删除，是回滚的唯一依据
4. **幂等操作只重试不回滚** —— 卸载这类重复执行无害的操作，失败后让用户重试即可

## 八、各操作对公共目录的影响汇总

| 操作 | 公共目录内容 | 回滚策略 |
|------|---------|---------|
| 安装 | 写入（可能先把冲突内容改名让位） | 撤销改名 + 删除刚落库的目录 |
| 更新 | 替换 | 快照 + 版本指针恢复 |
| 回退 | 替换 | 同更新，来源为历史 commit |
| 卸载 | 删除（真实内容，影响所有 AI 工具） | 不做回滚，仅重试 |
| 采纳 | 不修改，只读 SKILL.md 和内容哈希 | 不涉及写入公共目录，失败直接报告原因 |
