# Skillsage 开发阶段规划

> 2026-08-20：Phase 1-7 完成后，产品做了一次不属于此规划的重构——移除工具检测和
> 符号链接/目录联接分发（下文 Phase 2/4/6 中提到的 `core/tools/`、`core/distribute/`、
> "调整分发"、"批量分发"均已删除），改为所有技能直接安装到单一共享公共目录
> `~/.agents/skills/`。这是历史记录，如实保留 Phase 1-7 当时的实际设计；当前架构以
> `docs/specs/01-需求文档.md`、`03-后端架构.md`、`05-生命周期状态机.md` 和
> `docs/memory/decisions.md` 为准。

## 阶段划分原则

按**从内核到外壳、从核心到边缘**的原则，每个阶段都是可验证的里程碑，不依赖下一阶段就能独立测试。

---

## Phase 1：项目脚手架与设计系统落地

### 目标
跑起一个空壳应用，能看到页面、能切换深色浅色，为后续开发提供基线。

### 交付物
- Tauri 2 项目初始化（React + shadcn + pnpm + TypeScript）
- Tailwind 配置锁定设计 token（圆角变量 `--radius` / `--radius-lg`、阴影层级、颜色体系、4px 步进约束）
- 深色/浅色/跟随系统三模式切换，zustand store 管理
- 路由骨架：三个空页面（商店 / 管理 / 设置），左侧导航栏
- `ScrollArea` 全局滚动组件封装（禁止原生 overflow-auto）
- 项目文档目录 `docs/specs/` 初始化

### 可验证标准
启动应用 → 能看到三个页面之间切换 → 切换深色/浅色模式全局生效 → 所有组件使用统一圆角和间距规范。

---

## Phase 2：后端核心管线 + 端到端验证

### 目标
打通"下载 → 解析 → 落库 → 分发 → 记录"完整链路，用一个硬编码技能验证全流程通顺。

### 交付物
- `core/github/`：仓库文件树获取 + 技能目录下载
- `core/skill/parser.rs`：SKILL.md frontmatter 解析 + 校验
- `core/repo/`：中央仓库路径规则 + 原子落库
- `core/distribute/`：symlink / junction 平台分层 + 已建链接追踪
- `core/lockfile/`：lock 文件读写
- `core/lifecycle/install.rs`：安装状态机（含回滚）
- `core/tools/registry.rs`：5 个工具配置表
- `core/tools/detection.rs`：工具检测
- 以上所有模块的单元测试
- 前端一个"安装测试技能"按钮，直调后端

### 可验证标准
点击按钮 → 技能下载到 `~/.skillsage/remote/` → 对应工具目录下出现链接 → lock 文件正确写入 → 卸载后链接和目录全部清除。

---

## Phase 3：商店页

### 目标
用户能浏览技能、搜索、看详情、安装到指定工具。

### 交付物
- `core/store/`：skills.sh 搜索 API 客户端 + 详情页抓取 + 排行榜数据
- `commands/store.rs`：搜索、详情、排行榜三个 command
- 前端商店页：
  - 排行榜 Tab（热门/趋势/爆款）
  - 搜索框（实时请求 api/search）
  - 技能卡片列表（同一仓库聚合展示 "+N more from"）
  - 技能详情弹窗（描述、安装量、作者、安全审计、工具勾选）
  - 安装按钮 → 调用 Phase 2 的安装管线

### 可验证标准
打开商店 → 看到排行榜 → 搜索 react → 点击技能看到详情 → 勾选工具 → 安装成功 → 管理页能看到刚装的技能。

---

## Phase 4：技能管理页

### 目标
用户能管理已安装的技能，包括更新、回退、卸载、调整分发、批量操作。

### 交付物
- `core/lifecycle/update.rs`、`rollback.rs`、`uninstall.rs`
- `core/lifecycle/` 新增调整分发（增删链接）
- `commands/manage.rs`：列表、刷新、检查更新、更新、回退、卸载、调整分发
- 前端管理页：
  - 作者分组折叠列表（Accordion）
  - 紧凑表格行（技能名、描述、来源标签、分发状态、版本、操作菜单）
  - 顶部工具栏：搜索、筛选（来源/状态/工具）、排序、刷新按钮、导入入口
  - 行操作菜单：更新、回退版本、调整分发、卸载
  - 批量分发：选择模式 → 全选当前筛选结果 → 分发到指定工具
  - 版本历史对话框
  - 本地导入入口 + 导入对话框

### 可验证标准
安装多个技能 → 管理页按作者分组展示 → 搜索筛选正常 → 更新一个技能 → 回退到旧版本 → 调整分发（取消某个工具）→ 卸载 → 批量分发补发。

---

## Phase 5：设置、本地导入与 GitHub URL 安装

### 目标
补全三种安装来源，配好 Token 和代理。

### 交付物
- `core/import/`：本地导入（来源识别、SKILL.md 定位、同名冲突处理）
- `core/url_install/`：GitHub URL 解析 + 仓库内技能列表展示
- `core/settings/`：Token 加密存储（keyring）、代理配置持久化
- 前端设置页：GitHub Token 输入框、代理配置
- 前端本地导入流程：选择文件/目录 → 解析预览 → 确认导入
- 前端 GitHub URL 安装：输入框 → 解析 → 选择技能 → 安装

### 可验证标准
三种安装来源（商店 / GitHub URL / 本地导入）都能正常工作。Token 存储后重启应用仍可读取。代理配置后 GitHub 请求正常通过。

---

## Phase 6：高级功能（存量迁移 + 跨设备同步 + 冲突处理）

### 目标
解决存量用户和跨设备使用场景。

### 交付物
- `core/sync/`：导出 JSON 同步数据 + 导入（含工具检测、分发选择和非敏感设置）
- `core/migrate/`：存量技能扫描与迁移
- 安装/分发时冲突检测：非我们创建的条目 → 三选一弹窗（跳过/接管/取消）
- 前端迁移向导：扫描 → 分类展示 → 接管确认
- 前端导入预览页：同步数据展示 + 勾选 + 工具检测决策 + 应用设置恢复选项

### 可验证标准
迁移存量技能（npx 安装的）→ 导出同步数据 → 在新设备导入 → 同步数据中的技能正确安装和分发。应用设置按用户选择恢复，安装时遇到冲突条目能正确处理。

---

## Phase 7：打磨与 QA

### 目标
把所有边角补上，保证跨平台体验一致。

### 交付物
- 所有页面的空态（EmptyState）、加载态（Skeleton）、错误态（ErrorBanner）
- 卸载应用时的清理弹窗（清理全部 / 保留技能）
- 网络异常处理（GitHub 不可达、skills.sh 不可达、限流提示引导配置 Token）
- Windows 和 macOS 双平台测试
- 日志系统（tracing 落盘，方便用户反馈问题）
- 代码清理、文档补全、README

### 可验证标准
全功能走查一遍，所有错误路径有明确提示，双平台行为一致，卸载后无残留。

---

## 阶段依赖关系图

```
Phase 1（脚手架 + 设计系统）
  └── Phase 2（后端核心管线）—— 独立可验证
        ├── Phase 3（商店页）—— 依赖 Phase 2
        ├── Phase 4（管理页）—— 依赖 Phase 2
        └── Phase 5（设置/导入）—— 依赖 Phase 2
              └── Phase 6（高级功能）—— 依赖 Phase 3~5
                    └── Phase 7（打磨 QA）
```

### 并行建议

- **Phase 3 和 Phase 4 可以并行开发**：前端不同人负责不同页面，后端 commands 独立不交叉
- **Phase 5 可以和 Phase 3/4 的部分任务并行**：只要后端管线（Phase 2）已完成即可开始
- **Phase 6 必须在 Phase 3~5 之后**：它依赖所有安装来源都就绪

## 各阶段预估工作量参考

| 阶段 | 核心内容 | 复杂度 |
|------|---------|--------|
| Phase 1 | 项目初始化、Tailwind 配置、路由骨架 | 低 |
| Phase 2 | 后端核心模块、安装管线、单元测试 | **高**（最关键阶段）|
| Phase 3 | 商店页前后端联调 | 中 |
| Phase 4 | 管理页（最复杂的 UI 页面）| **高** |
| Phase 5 | 设置页、三种安装来源补全 | 中 |
| Phase 6 | 迁移、同步、冲突处理 | 中~高 |
| Phase 7 | 边角打磨、双平台测试 | 中 |
