# Skillsage 后端架构

> 2026-08-20 更新：随"单一共享目录"重构，`core/tools/`、`core/distribute/`、
> `core/lifecycle/distribute.rs` 已删除，`core/repo/` 新增 `conflict.rs`。详见
> `docs/memory/decisions.md`。

## 一、总体分层

```
┌─────────────────────────────────────────────┐
│ commands 层（薄壳）                          │
│  Tauri command 入口：参数解析、调用 core、    │
│  序列化返回、事件推送。不写业务逻辑            │
├─────────────────────────────────────────────┤
│ core 层（纯 Rust 领域逻辑，不依赖 tauri）     │
│  商店、下载、解析、生命周期、同步、采纳        │
│  —— 可独立单元测试，未来可复用                │
├─────────────────────────────────────────────┤
│ 基础设施：路径、错误类型、设置存储、日志       │
└─────────────────────────────────────────────┘
```

core 层不依赖 tauri crate —— 所有核心逻辑都能脱离 GUI 单独测试。

## 三、模块职责详解

### store/ — skills.sh 客户端

**client.rs**：HTTP 客户端封装，支持代理注入、超时控制、自动重试。

**search.rs**：对接 `https://skills.sh/api/search?q=<关键词>` JSON 接口，解析搜索结果。

**detail.rs**：抓取 `https://www.skills.sh/<作者>/<仓库>/<技能名>` HTML 页面，提取技能描述、安装量、GitHub Stars、安全审计结果等字段。

### github/ — GitHub 拉取

**client.rs**：封装 GitHub API 和 raw.githubusercontent.com 请求，支持 Token 注入。

**tree.rs**：获取仓库文件树，定位技能目录在仓库中的路径。

**download.rs**：下载技能目录全部文件到指定目标路径。

### skill/ — SKILL.md 领域模型

**model.rs**：Skill 结构体定义（name、description、license、compatibility、metadata 等）。

**parser.rs**：
- 解析 YAML frontmatter 提取元数据
- 校验规则：name 必须符合 kebab-case（`^[a-z0-9]+(-[a-z0-9]+)*$`）、description 非空且 ≤1024 字符
- 透传 metadata 自由键值对
- 校验失败返回结构化错误信息

### repo/ — 路径规则与本地管理数据

**layout.rs**：`RepoLayout { root, public_root }`。`public_root`（`~/.agents/skills`）是所有技能内容的唯一位置，`skill(name)` 是唯一的路径访问器——不再区分 remote/local 两套路径规则。`root`（`~/.skillsage`）只保存 lock、快照、临时目录和设置，`ensure_roots()` 会在 `public_root` 的父目录（`~/.agents`）缺失时先无守卫地创建它，再对 `public_root` 本身做与其他受管根一致的"拒绝符号链接"检查。

**conflict.rs**：`is_tracked()` 判断某个名称是否已被 lock 记录跟踪（供安装前置检查和采纳扫描共用过滤条件）；`check()` 检查目标路径是否被未跟踪内容占用；`take_over()` 把占用内容改名保留（`<名称>.skillsage-backup-<时间戳>`），从不删除、也从不原地接管别人的内容。

**atomic.rs**：
- 创建临时目录 `~/.skillsage/tmp/<pid>-<纳秒>/`
- 原子落库：优先用 `rename` 保证原子性；若目标跨卷（`~/.skillsage/tmp` 与 `~/.agents/skills` 理论上可能不在同一分区）则退化为递归复制 + 删除源
- 清理临时目录

**lockfile.rs**：
- lock 文件读写（JSON 格式，version 字段用于拒绝旧格式，见下）
- 版本指针历史 append 操作
- 内容 hash 计算（blake3）与对比

> 旧版本 lock 文件（`version: 1`，含 `distributedTo` 字段）不会被解析——`load()` 遇到非当前版本直接视为空锁文件。这是"干净切换"的诚实实现：旧的 `~/.skillsage/remote|local` 内容和旧工具目录符号链接留在磁盘上但不再被跟踪，不做自动搬迁。

### lifecycle/ — 生命周期状态机

四条流程共享同一套底层模块调用模式：

| 流程 | 核心步骤 | 回滚策略 |
|------|---------|---------|
| install | 下载→解析→校验命名冲突→处理路径冲突→落库→写lock | 已接管内容/临时目录逆序撤销 |
| update | 备份(快照+版本指针)→下载→替换→更新lock | 快照恢复 |
| rollback | 拉 commit 内容→备份→替换→更新lock | 同 update |
| uninstall | 读lock→删公共目录中的技能文件夹→删快照→删lock | 不做回滚，仅重试 |

`uninstall` 现在删除的是公共目录里的真实文件夹，不再是一个可随时重建的链接——所有读取该目录的 AI 工具会立即失去这个技能。

### import/ — 本地导入

**source.rs**：识别用户选择的来源类型（目录或单文件 SKILL.md），并提供 `validate_tree()` 校验目录树中不含符号链接——同一校验也被采纳扫描复用，用来提前发现不安全的候选项。

**resolver.rs**：
- 定位 SKILL.md 文件
- 同名冲突检测（第一层，已跟踪的记录）：已存在同名技能 → 弹窗让用户选择"覆盖"或"重命名"
- 路径冲突检测（第二层，未跟踪的内容）：解析后的最终名称若被公共目录中未跟踪的内容占用，走与安装相同的跳过/备份后继续/取消流程
- 以 frontmatter 的 name 为权威标识

### url_install/ — GitHub URL 安装

**parser.rs**：URL 解析为统一结构体：
```rust
struct GitHubUrlResult {
    owner: String,
    repo: String,
    skill_path: Option<String>,  // None 表示未指定具体技能
    commit: String,              // 默认 main
}
```
支持格式：完整仓库 URL、带 tree/blob 路径的精确技能 URL、SKILL.md 直接链接。

**resolver.rs**：完整仓库 URL 时，调 GitHub API 列出该仓库下的技能目录供用户选择。

### sync/ — 跨设备同步

**export.rs**：遍历所有 remote 技能的 lock 记录，生成 JSON 同步数据（含描述、版本和非敏感应用设置），不含实际内容、GitHub Token，也不再含分发目标。导出路径由前端文件保存选择器传入。

**import.rs**：解析 JSON 同步数据 → 展示预览 → 用户选择技能和是否恢复应用设置 → 逐个走标准安装流程，不再有"检测工具/决定分发给谁"这一步。

### migrate/ — 存量技能"采纳"

**scanner.rs**：只扫描公共目录 `~/.agents/skills/`（不再扫描任何工具专属目录，因为已经没有工具专属目录了）。跳过符号链接和非目录条目——那不是我们能判断是否安全删除的东西。对每个未被跟踪的真实目录，先用 `import::source::validate_tree()` 排除含符号链接的树，再尝试解析 SKILL.md；文件夹名始终是权威的技能名（采纳不移动文件，SKILL.md 里声明的名称如果不同，只作为提示信息，不采用）。

**classifier.rs**：尝试匹配其他工具自己的锁文件格式（`~/.agents/*.json` 等几种候选路径），从中恢复可能的 GitHub 来源线索（owner/repo/commit）。这只是一个线索，不直接采信。

**migrator.rs**：原地登记——**不做 `fs::rename`，不重建任何链接**。对 classifier 给出的来源线索，会实际重新拉取一次对应 commit 的内容，用内容哈希比对确认与磁盘上的实际内容一致才采信为远程来源；不一致或拉取失败则退化为本地来源记录。这是一个只读增益：最坏情况等价于完全不做来源恢复，最好情况让被采纳的技能也能继续检查更新和回退。

## 四、统一错误类型

```rust
enum SkillsageError {
    // 网络
    NetworkError(String),
    RateLimited,              // GitHub 限流
    StoreUnavailable,         // skills.sh 不可达

    // GitHub
    GithubAuthMissing,
    GithubApiError(u16),      // HTTP 状态码
    RepositoryNotFound,

    // 解析
    InvalidSkillMd(String),   // 具体缺失字段
    NameConflict(String),     // 名称已被已跟踪的记录占用
    InstallConflict(String),  // 名称已被未跟踪的内容占用（公共目录路径冲突）

    // 文件系统
    PermissionDenied(PathBuf),
    PathNotFound(PathBuf),

    // 生命周期
    AlreadyInstalled,
    NotInstalled,
    UpdateNotAvailable,

    // 导入/同步
    ImportInvalidSource,
    ExportFailed,
    ImportFailed,
}
```

`LinkCreationFailed`/`LinkRemovalFailed`/`UnknownTool` 已随分发机制一起移除。每种错误携带前端展示所需的信息，通过 error.rs 统一映射为用户可读文案。

## 五、并发控制

- **写操作串行化**：安装/更新/回退/卸载/导入/采纳经一把全局异步锁（tokio::sync::Mutex）串行化
- **读操作不加锁**：列表/详情/检查更新/扫描采纳候选可并发
- **UI 配合**：某技能处于操作中时，其操作按钮禁用

## 六、进度事件

安装、更新这类耗时操作通过 Tauri 事件推送给前端，事件内容为**阶段变化**而非精细百分比：

```
downloading → parsing → distributing → done / failed
```

`distributing` 阶段名称沿用自旧模型，现在代表"写入公共目录"，技能都是小文件，阶段级进度足够。
