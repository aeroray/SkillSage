# Skillsage 后端架构

## 一、总体分层

```
┌─────────────────────────────────────────────┐
│ commands 层（薄壳）                          │
│  Tauri command 入口：参数解析、调用 core、    │
│  序列化返回、事件推送。不写业务逻辑            │
├─────────────────────────────────────────────┤
│ core 层（纯 Rust 领域逻辑，不依赖 tauri）     │
│  商店、下载、解析、分发、生命周期、同步        │
│  —— 可独立单元测试，未来可复用                │
├─────────────────────────────────────────────┤
│ 基础设施：路径、错误类型、设置存储、日志       │
└─────────────────────────────────────────────┘
```

core 层不依赖 tauri crate —— 所有核心逻辑都能脱离 GUI 单独测试。

## 三、模块职责详解

### tools/ — 工具注册与检测

**registry.rs**：5 个内置工具的结构化配置，每个工具包含 id、显示名称、全局 skills 目录路径。追加新 AI 工具只需在此文件加一条配置。

**detection.rs**：启动时异步执行，检查各工具全局 skills 目录是否存在。检测结果驻留内存，供商店详情页默认勾选、管理页分发状态展示等场景复用。

### store/ — skills.sh 客户端

**client.rs**：HTTP 客户端封装，支持代理注入、超时控制、自动重试。

**search.rs**：对接 `https://skills.sh/api/search?q=<关键词>` JSON 接口，解析搜索结果。

**detail.rs**：抓取 `https://www.skills.sh/<作者>/<仓库>/<技能名>` HTML 页面，提取技能描述、安装量、GitHub Stars、安全审计结果等字段。

### github/ — GitHub 拉取

**client.rs**：封装 GitHub API 和 raw.githubusercontent.com 请求，支持 Token 注入。

**tree.rs**：获取仓库文件树，定位技能目录在仓库中的路径。

**download.rs**：下载技能目录全部文件到指定目标路径。

### skill/ — SKILL.md 领域模型

**model.rs**：Skill 结构体定义（name、description、license、compatibility、metadata 等）。

**parser.rs**：
- 解析 YAML frontmatter 提取元数据
- 校验规则：name 必须符合 kebab-case（`^[a-z0-9]+(-[a-z0-9]+)*$`）、description 非空且 ≤1024 字符
- 透传 metadata 自由键值对
- 校验失败返回结构化错误信息

### repo/ — 中央仓库

**layout.rs**：定义 remote（按作者组织）和 local（扁平结构）的路径生成规则。

**atomic.rs**：
- 创建临时目录 `~/.skillsage/tmp/<uuid>/`
- 原子落库：临时目录内容移动到最终位置（使用 rename 保证原子性）
- 清理临时目录

**lockfile.rs**：
- lock 文件读写（JSON 格式）
- 版本指针历史 append 操作
- 内容 hash 计算（blake3）与对比

### distribute/ — 链接分发

**link.rs**：平台分层的链接创建与删除：
- macOS：`std::os::unix::fs::symlink`
- Windows：`std::process::Command` 调用 `mklink /J` 创建 junction；删除用 `std::fs::remove_dir`

**tracker.rs**：记录每次操作已建的链接清单（工具 id + 链接绝对路径），用于回滚和卸载时逆序清理。

### lifecycle/ — 生命周期状态机

四条流程共享同一套底层模块调用模式：

| 流程 | 核心步骤 | 回滚策略 |
|------|---------|---------|
| install | 下载→解析→落库→建链接→写lock | 已建清单逆序撤销 |
| update | 备份(快照+版本指针)→下载→替换→更新lock | 快照恢复 |
| rollback | 拉 commit 内容→备份→替换→更新lock | 同 update |
| uninstall | 读lock→删链接→删目录→删lock | 不做回滚，仅重试 |

### import/ — 本地导入

**source.rs**：识别用户选择的来源类型——目录或单文件 SKILL.md。

**resolver.rs**：
- 定位 SKILL.md 文件
- 同名冲突检测：local 区已存在同名技能 → 弹窗让用户选择"覆盖"或"重命名"
- 以 frontmatter 的 name 为权威标识

### url_install/ — GitHub URL 安装

**parser.rs**：URL 解析为统一结构体：
```rust
struct GitHubUrlResult {
    owner: String,
    repo: String,
    skill_path: Option<String>,  // None 表示未指定具体技能
    commit: String,              // 默认 main
}
```
支持格式：完整仓库 URL、带 tree/blob 路径的精确技能 URL、SKILL.md 直接链接。

**resolver.rs**：完整仓库 URL 时，调 GitHub API 列出该仓库下的技能目录供用户选择。

### sync/ — 跨设备同步

**export.rs**：遍历所有 remote 技能的 lock 记录，生成 JSON 同步数据（含描述、版本、分发记录和非敏感应用设置），不含实际内容或 GitHub Token。导出路径由前端文件保存选择器传入。

**import.rs**：解析 JSON 同步数据 → 展示预览 → 用户选择技能和是否恢复应用设置 → 逐个走标准安装流程。

### migrate/ — 存量技能迁移

**scanner.rs**：扫描 5 个工具目录 + `~/.agents/skills/` 公共目录。

**classifier.rs**：按条目形态分类：
- 我们创建的链接（指向 `~/.skillsage/`）→ 跳过
- 指向公共目录的链接 → 追溯到公共目录接管实体
- 真实目录（复制）→ 查 npx lock 判归属
- 未知来源链接 → 标记，提供删除选项

**migrator.rs**：接管实体 → 移入中央仓库 → 重建链接。与分发冲突接管共用同一套核心逻辑。

## 四、统一错误类型

```rust
enum SkillsageError {
    // 网络
    NetworkError(String),
    RateLimited,              // GitHub 限流
    StoreUnavailable,         // skills.sh 不可达

    // GitHub
    GithubAuthMissing,
    GithubApiError(u16),      // HTTP 状态码
    RepositoryNotFound,

    // 解析
    InvalidSkillMd(String),   // 具体缺失字段
    NameConflict(String),

    // 文件系统
    PermissionDenied(PathBuf),
    PathNotFound(PathBuf),

    // 分发
    LinkCreationFailed(PathBuf),
    LinkRemovalFailed(PathBuf),

    // 生命周期
    AlreadyInstalled,
    NotInstalled,
    UpdateNotAvailable,

    // 导入/同步
    ImportInvalidSource,
    ExportFailed,
    ImportFailed,
}
```

每种错误携带前端展示所需的信息，通过 error.rs 统一映射为用户可读文案。

## 五、并发控制

- **写操作串行化**：安装/更新/回退/卸载/导入/批量分发/调整分发经一把全局异步锁（tokio::sync::Mutex）串行化
- **读操作不加锁**：列表/详情/检查更新可并发
- **UI 配合**：某技能处于操作中时，其操作按钮禁用

## 六、进度事件

安装、更新这类耗时操作通过 Tauri 事件推送给前端，事件内容为**阶段变化**而非精细百分比：

```
downloading → parsing → distributing → done / failed
```

技能都是小文件，阶段级进度足够。
